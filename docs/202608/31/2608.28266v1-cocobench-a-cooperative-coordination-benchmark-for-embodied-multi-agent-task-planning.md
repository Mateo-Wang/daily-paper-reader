## 摘要
近年来，基于多模态大语言模型（MLLM）的智能体系统发展迅速，但现有的具身智能体基准仍缺乏对多智能体协调的细粒度诊断。大多数基准要么聚焦于单智能体任务完成，要么通过整体任务成功率来概括多智能体行为，这可能会掩盖诸如重复劳动、顺序约束违反、资源竞争和交接不同步等协调失败。在本文中，我们引入了CoCoBench，这是一个用于评估可执行家庭任务中多智能体具身协调的构造级基准。CoCoBench包含897个经过预言机验证的实例，围绕四个反复出现的协调构造组织：任务分配、顺序排序、互斥和交接协调。除了任务成功率外，CoCoBench还提供了构造级分数，用于衡量智能体是否有效协调。我们评估了11个领先的MLLM在不同协调模式、观察输入和智能体数量下的表现。结果表明，协调能力具有高度的构造特异性：整体性能优秀并不意味在不同协调类型上具备均衡的能力。这些发现为设计有针对性的模型架构和提升多智能体协调能力指明了新方向。

## Abstract
Agent systems powered by multimodal large language models (MLLMs) have advanced rapidly in recent years, yet existing embodied-agent benchmarks still lack fine-grained diagnostics for multi-agent coordination. Most benchmarks either focus on single-agent task completion or summarize multi-agent behavior with overall task success rates, which can obscure coordination failures such as duplicated work, violations of ordering constraints, resource contention, and desynchronized handoffs. In this paper, we introduce CoCoBench, a construct-level benchmark for evaluating multi-agent embodied coordination in executable household tasks. CoCoBench contains 897 oracle-validated instances organized around four recurring coordination constructs: task allocation, sequential ordering, mutual exclusion, and handoff coordination. In addition to task success rate, CoCoBench provides construct-level scores that measure whether agents coordinate effectively. We evaluate 11 leading MLLMs across different coordination modes, observation inputs, and numbers of agents. The results show that coordination ability is highly construct-specific: strong overall performance does not imply balanced competence across different coordination types. These findings point to new directions for designing targeted model architectures and improving multi-agent coordination ability.

## 2. 方法论：核心思想、关键技术细节与评分公式

- **问题形式化**：将多智能体具身协调建模为高层联合决策问题，任务实例被定义为 \(x = (E, A, S, O, U, \Delta, \Phi, H, d)\)。协调耦合（coordination coupling）被形式化定义为一个智能体的动作改变另一个智能体动作的有效性/效用/成本的性质。评估输出为 \((Succ_x(\tau), C_{d,x}(\tau))\) 二元组——任务完成状态与构造级协调分数分离。
- **四个协调构造（Coordination Constructs）**：
  - **D1 任务分配（Task Allocation）**：独立子任务在团队中的均衡分配，避免重复劳动和串行化；
  - **D2 顺序排序（Sequential Ordering）**：智能体须共同遵守因果前置条件（如先开抽屉、放入全部物体后才关闭）；
  - **D3 互斥（Mutual Exclusion）**：共享独占资源（如单把刀具）上的无冲突调度；
  - **D4 交接协调（Handoff Coordination）**：通过中间缓冲区进行的生产者-消费者式交接，须防止缓冲溢出和空等。
- **构造级评分公式**：
  - \(C_{D1} = \min(1, M^*/M)\)：实际完成时间与 oracle 参考完成时间之比，衡量分配均衡度；
  - \(C_{D2} = p_{legal}(1 - v/n)\)：合法门（无越权技能使用与前置条件违规）乘以顺序违规惩罚项；

## 6. 主要结论与发现

- **协调能力高度构造特异**：整体性能最优不意味各协调类型上都表现均衡。例如 Qwen3-VL-8B 在 D1 上取得最佳 SR 与 CS（95.0%/0.91），但在 D4 上为 0%；GPT-5.6-sol 在 D3/D4 上领先，却在 D1 上远逊于 Qwen3-VL-8B。性能不跨构造迁移。
- **集中式状态聚合仍然重要**：集中式策略在 240 子集上平均取得 48.0% SR / 0.69 CS，优于分散式+通信（39.6% / 0.65）和纯分散式（36.7% / 0.63）。通信有效但只能部分弥补集中式信息聚合的缺失。
- **符号协调是主要瓶颈**：移除视觉观测并未降低性能（盲输入 42.3% SR / 0.660 CS vs 图像 40.6% / 0.655）。在高层技能接口下，任务相关信息已显式接地，主要瓶颈在符号级团队规划而非低级视觉识别。
- **团队规模增大加剧协调负担**：平均 SR 从两智能体 48.8% 降至四智能体 43.1%，CS 从 0.68 降至 0.63。强模型（GPT-5.6-sol、Claude Opus 4.8）相对稳定，弱开源模型衰减更显著（如 InternVL3.5-8B 从 16.9% 降至 7.7%）。
- **任务成功与合法协调相分离**：部分模型"成功率高但合法性低"，意味着通过捷径/非法动作达成了目标状态（如 Qwen3-VL-8B 24.6% SR vs 13.0% 合法率）；另一些模型"合法但未成功"（Claude Opus 4.8 96.3% 合法率 vs 78.5% SR）。总体成功率会高估或低估真实的协调能力。
- **失败模式暴露模型类别差异**：开源模型平均 17.5% 协议失败和较高预算耗尽率（最高 61%），专有模型协议失败几乎为零（平均 1.0%），显示弱模型在遵守高层动作协议和步骤预算方面存在明显短板。

## 7. 优点

- **构造级评估设计**：每个任务只定向测量一种协调构造，通过符号模板生成并验证，避免多个依赖机制混杂在单一任务中导致的诊断混淆，优于 MECoBench 等现有工作。
- **双指标分离**：将任务成功率（是否达成目标）与构造分数（协调质量如何）解耦，能识别"成功但不合法/低效"与"合法但不完整"的轨迹，提升评估的诊断能力。
- **指标非冗余验证**：用 GPT-5.6-sol 的 897 条轨迹交叉应用四个评分函数，证明四构造相关性极低，说明测试的不是一个单一潜在因子或任务成功率的另一编码形式。
- **系统化的消融设计**：控制协调模式（集中/分散）、观察输入（图像/盲）、团队规模三轴做消融，使结论有据可依。
- **可复现性**：固定低级执行器、确定性轨迹记录与评分，结果可从轨迹重算；提供开源代码。
- **实例质量控制严格**：三重验证门（放置门、oracle 门、指标门）过滤了不可行、歧义和弱诊断的实例，优先保证构造效度。

## 8. 不足与局限

- **模拟器局限**：基于 AI2-THOR，物体状态空间、交互类型和物理保真度有限，结论向真实机器人场景的迁移性未知。
- **高层技能接口的假设**：固定高层技能库并显式暴露动作菜单，可能低估视觉感知与低级技能执行的作用——作者也承认主要瓶颈在符号级规划，但这一结论仅在该接口假设下成立。
- **消融覆盖不完整**：架构消融和观察消融仅用了 4 个模型（240 子集），未覆盖全部 11 个模型，可能遗漏模型间异质效应。
- **oracle 最优性声明有限**：仅对 D1 保证参考 makespan 最优，D2–D4 未声称全局最短（既非高层技能数最短，也非导航里程最短），构造分数的参考上界可能非最优。
- **时间成本不可横向比较**：wall-clock 数据混合了硬件与 API 延迟，且明确不可在专有与开源模型之间比较，限制了效率维度的结论价值。
- **评估通道受限**：D4 使用角色条件化的任务菜单，而 D1–D3 使用同质菜单，协议间差异可能影响模型的绝对可比性。
- **模型可复现性存疑**：所评测的多个专有模型版本（GPT-5.6-sol、Claude Opus 4.8、Qwen3.6-Plus、Kimi-K2.6 等）在现实中不存在或未公开，第三方难以精确复现报告数据。
