## 摘要
自动驾驶车辆需要强大的感知和决策能力，以在多样化和未见过的场景中运行。虽然强化学习和基于规则的方法可以提供有效的控制和安全机制，但在需要上下文推理的情况下，其性能可能会下降。大型语言模型（LLM）在理解多模态信息和生成上下文推理方面表现出了强大的能力，然而，将其用于直接车辆控制可能会带来延迟和幻觉风险。为了解决这些局限性，提出了一种混合框架。该系统使用一个编排器来协调经过PPO训练的强化学习和PID控制，并在整个框架中应用LLM常识推理。进一步迭代地利用LLM推理来优化动态驾驶环境下的强化学习奖励函数。所提出的框架在高度随机的CARLA场景中，在多样化的环境和交通条件下进行了评估。结果表明，将基于LLM的推理与传统的自动驾驶方法相结合，同时保留结构化的控制和安全机制，具有潜力。

## Abstract
Autonomous vehicles require robust perception and decision-making capabilities to operate in diverse and unseen scenarios. While reinforcement learning and rule-based methods can provide effective control and safety mechanisms, their performance may degrade in situations requiring contextual reasoning. Large Language Models (LLMs) have demonstrated strong capabilities in understanding multimodal information and generating contextual reasoning, however, their use for direct vehicle control can introduce latency and hallucination risks. To address these limitations, a hybrid framework is proposed. This system uses an orchestrator to coordinate PPO-trained reinforcement learning and PID control, with LLM common-sense reasoning applied throughout the framework. LLM reasoning is further employed iteratively to refine the RL reward function for dynamic driving environments. The proposed framework is evaluated in highly randomized CARLA scenarios under diverse environmental and traffic conditions. The results demonstrate the potential of integrating LLM-based reasoning with conventional autonomous driving methods while retaining structured control and safety mechanism.

## 2. 论文提出的方法论

### 2.1 总体架构
- 分为**离线开发阶段**与**运行时执行阶段**。
- 运行时由四层构成：**感知层 → 多智能体推理层 → 编排器 → 控制执行层**。
- 决策权在编排器，LLM 不参与实时控制。

### 2.2 感知层
- 使用 **YOLOv11**（Roboflow 训练）进行物体检测（车辆、行人、自行车、红绿灯）。
- 车道检测：边缘检测 + 多项式拟合，计算中心偏移与曲率。
- 交叉口检测：估计车道宽度、识别横道线等路面标记。
- 三者输出融合为统一感知状态。

### 2.3 多智能体层
四个独立并行运行的智能体，对应不同 ASIL 安全等级：

| 智能体 | ASIL | 职责 |
|---|---|---|
| Safety Agent | ASIL-D | 碰撞风险评估（TTC 阈值分级）、常识规则检查、整体风险评分 |
| Situation Agent | ASIL-C | ODD 合规评估、天气/光照/路况/交通密度等环境情境分析 |
| Planning Agent | ASIL-B | 目标速度选择、动作与转向决策 |
| Behavior Agent | ASIL-A | 驾驶舒适性评估（基于转向方差的平滑性指标） |

Safety Agent 的整体风险公式：
```
Rholistic = min(0.5·Rcollision + 0.1·Nfaults + 0.2·Lperception + Rtraffic + Rintersection, 1.0)
```
- `Rcollision`：TTC 与距离综合碰撞风险
- `Nfaults`：传感器故障数
- `Lperception`：感知受限程度
- `Rtraffic`：红灯时取 0.15
- `Rintersection`：处于交叉口时取 0.1

### 2.4 编排器（Orchestrator）
- 采用 ASIL 加权优先级融合，每个智能体 i 的权重：
```
wi = wbase,i · mASIL,i · ci · bconflict,i
```
- 基础权重：Safety 2.5 > Situation 1.5 > Planning 1.2 > Behavior 0.8
- ASIL 乘数：ASIL-D 2.0 > ASIL-C 1.5 > ASIL-B 1.2 > ASIL-A 1.0
- 安全否决权：ASIL-D/C 智能体在阈值以上推荐停车时，可强制停车。

### 2.5 控制层
- 对比了四种控制策略：Base PID（纯 PID）、Curve PID（PID+RL 转向）、Speed PID（PID+RL 速度）、Hybrid PID+RL。
- **两个独立的 PPO actor-critic 网络**分别负责纵向（速度）和横向（转向）控制，输入为归一化的状态向量（表 3）。

### 2.6 LLM 集成方式

**（1）奖励精化（GPT-5.2）**
- 初始 RL 模型 V0 在 1000 episode CARLA 数据训练（无 LLM 引导）。
- GPT-5.2 对训练摘要进行分析，给出奖励调整建议；经过 V0 → V1 → V2 → V3 共四轮迭代。
- 修改内容涉及：转向振荡惩罚、jerk 惩罚、车道偏差二次惩罚、曲率一致性奖励、曲线自适应前瞻距离、带质量门控的进度奖励等。

**（2）常识规则生成（Claude）**
- Claude 生成覆盖信号灯、天气、夜间行驶、跟车距离、行人、自行车、交叉口等场景的规则。
- 筛选出约 **100 条**可在 CARLA 执行的规则，集成到 Safety Agent 中，由 Safety Agent 最高优先级执行。

## 6. 主要结论

1. **LLM 离线引导奖励精化有效**：V3 在训练末期取得最低的车道误差（中位 0.0627，较 V0–V2 改善约 15–20%），同时保持最高的曲线暴露度（中位 160 步）和较优的转向稳定性。
2. **充分权衡的曲线驾驶能力**：V3 在跟踪精度、转向稳定性和曲线推进之间达到最佳平衡；V0 表面上的低振荡指标实际上由其低曲线暴露（113 步）所致。
3. **LLM 常识规则可被结构化执行**：约 100 条可执行规则能安全地集成到 Safety Agent 中，具有最高优先级，恶劣天气情境下能有效改变驾驶行为。
4. **混合路径可行**：将 LLM 推理与 PID/RL 结构化控制结合是一条具有潜力的技术路径，既提升推理能力又保留可审计的安全机制。

## 7. 优点

- **架构设计合理**：LLM 完全从实时执行环中解耦，规避延迟和幻觉风险；运行时由确定性多智能体系统接管。
- **安全优先**：ASIL-D/C 智能体拥有否决权，符合 ISO 26262/ASIL 分级设计理念。
- **可追溯性**：每个智能体产生推荐、置信度与推理轨迹；决策融合可追溯，面向工业级安全审计。
- **迭代闭环**：奖励精化过程融合了 LLM 分析 + 人工验证 + 重新训练，体现了"模拟-分析-改进"的闭环方法论。
- **常识规则落地**：将 LLM 生成的直观经验知识映射为仿真可执行规则，并针对 CAPLA 能力做了剔除与筛选，具有工程可实施性。

## 8. 不足与局限

- **仿真局限**：仅在 CARLA 中验证，缺少真实道路测试，仿真与现实的差距（感知噪声、动态交互、人为因素）未被覆盖。
- **实验覆盖不足**：没有系统化的多场景统计表（按天气/光照/交通密度的分组对比），也缺少与已有 SOTA 方法的端到端对比。
- **安全评估不完整**：未报告碰撞率、紧急停车次数、ODD 违例数量等直接安全指标。
- **依赖人为验证**：LLM 的奖励调整与规则筛选需要人工复核，可能引入主观偏差，且过程不易自动化、定价昂贵。
- **算力透明性差**：未报告训练成本、硬件配置与推理时延，复现门槛较高。
- **决策架构偏保守**：LLM 仅作为离线分析工具和规则生成器，在动态开放场景中的"深度推理"能力仍有较大上升空间；未来需要探索更安全、渐进式地增加 LLM 在线决策权限。
