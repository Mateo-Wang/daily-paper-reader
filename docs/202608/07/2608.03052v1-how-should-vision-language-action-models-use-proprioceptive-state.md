## 摘要
近期的视觉-语言-动作（VLA）模型几乎普遍将机器人本体感觉状态作为输入，但以互不兼容的方式接入——序列化为文本提示、投影到视觉-语言前缀中，或直接馈送给动作专家——且几乎总是作为单个当前帧。三个问题仍然悬而未决：（1）当前状态是否以及在哪些任务上确实改善了闭环控制；（2）状态历史有多大帮助，其益处是否反映真实的时序变化而非附加的条件容量；（3）状态应在模型的何处进入——视觉-语言主干还是动作生成模块。我们通过在流匹配VLA上进行受控实验来回答这些问题，全程固定主干、训练数据、动作表示和评估协议。我们在匹配的实现细节下实现了五种代表性接口——离散状态提示、VLM前缀、动作前缀、状态专家和特征调制——并在涵盖三个任务族共45个原子任务加上20个复合任务上评估它们；然后我们将状态历史长度从1帧扫描到96帧，以检验历史状态信息如何影响模型性能。实验对这三个问题给出了系统性的答案，并提炼成可测试的状态感知VLA设计原则。

## Abstract
Recent Vision-Language-Action (VLA) models almost universally take robot proprioceptive state as input, yet wire it in incompatible ways -- serialized into text prompts, projected into the vision-language prefix, or fed directly to the action expert -- and almost always as a single current frame. Three questions remain open: (1) whether, and on which tasks, current state actually improves closed-loop control; (2) how much state history helps, and whether its benefit reflects genuine temporal variation rather than added conditioning capacity; and (3) where state should enter the model -- the vision-language backbone or the action-generation module. We answer these questions through controlled experiments on a flow-matching VLA, fixing the backbone, training data, action representation, and evaluation protocol throughout. We implement five representative interfaces -- discrete state prompt, VLM prefix, action prefix, state expert, and feature modulation -- under matched implementation details, and evaluate them on 45 atomic tasks spanning three task families plus 20 composite tasks; we then sweep the state-history length from 1 to 96 frames to examine how historical state information affects model performance. The experiments yield systematic answers to all three questions, distilled into testable design principles for state-aware VLAs.

## 1. 核心问题与整体含义

- **背景**：近期的 VLA（视觉-语言-动作）模型几乎普遍将机器人本体感觉状态（如关节角、末端执行器位姿、夹爪开度）作为输入，但不同模型接入方式差异巨大：
  - **表示层面**：有的离散化为文本 token（如 π0.5），有的投影为连续嵌入（如 OpenVLA-OFT、GR00T N1）。
  - **注入位置**：有的输入 VLM 侧参与多模态上下文建模，有的直接送入动作专家。
  - **时间维度**：绝大多数方法仅使用当前单帧状态，很少利用历史状态。
- **核心问题**：在固定其他所有因素的前提下，机器人状态应如何表示、应在何处注入、需要多少历史帧，才能真实有效地提升 VLA 的闭环控制决策？
- **论文意义**：首次在统一受控实验框架下，系统解耦了状态接口、历史深度和注入位置三个设计变量，给出了可检验的实证设计原则，为后续状态感知 VLA 的设计提供了重要参考。

## 2. 方法论

### 核心思想
- 采用**流匹配 VLA（π0.5）**作为基础测试平台，固定骨干网络、训练数据、动作表示和评估协议，只改变状态的表示与接入方式。
- 将三个开放问题操作化为三个受控变量：
  - 状态表示（离散 vs. 连续）
  - 历史长度 K（1～96 帧）
  - 注入位置（VLM 侧 vs. 动作侧）

### 状态表示细节
- 原始状态帧为 16 维：末端执行器位置+四元数、移动基座位置+四元数、两个夹爪关节位置。
- 连续接口统一使用相同的状态序列，每帧独立经过两层投影器：
  \[
  h_i = \phi_2(\text{Swish}(\phi_1(s_i)))
  \]
- 维度匹配：VLM 前缀投影宽度为 2048；动作前缀、状态专家、特征调制投影宽度为 1024。

### 五种状态接口
1. **状态提示（State Prompt, sp）**：将当前状态逐维量化到 256 bin，序列化为约 66 个文本 token，加到语言提示中；不新增可训练参数，仅支持单帧。
2. **VLM 前缀（VLM Prefix, vp）**：连续状态 token 插入 VLM 双向前缀，先参与多模态上下文建模，再间接影响动作生成。
3. **动作前缀（Action Prefix, ap）**：状态 token 放入动作专家因果后缀中，直接在每一步去噪时参与速度场预测，是状态到动作的最直接路径。
4. **状态专家（State Expert, se）**：增加独立的状态处理 transformer 流，与动作模块交换信息，容量最大。
5. **特征调制（Feature Modulation, fm）**：状态不作为普通序列 token，而是通过交叉注意力预测每特征缩放 γ 和偏移 β，持续调制动作特征：
   \[
   \text{Mod}(z; S) = (1+\gamma(z,S)) \odot z + \beta(z,S)
   \]

### 历史扫描设计
- 历史长度 K 从 1 到 96 帧递增扫描。
- 使用 **slot-matched repeat-current 控制**：将当前状态重复填入相同数量的 slot，以区分“真实时序变化”与“额外条件容量”的贡献。

## 3. 实验设计

### 评测基准
- 基于 **RoboCasa365** 仿真平台（含多种厨房场景、机器人初始构型、物体实例与操作任务）。
- 视觉输入：左外部相机、右外部相机、腕部相机三个视角。
- 动作空间：末端执行器 delta 动作，部分实验使用关节角状态表示。

### 原子任务（Atomic Benchmark）
- 共 **45 个原子任务**，按控制语义预分为三个任务族：
  - **A. 重排/抓取放置**（大范围末端/基座定位）
  - **B. 铰接物体交互**（持续接触与运动阶段建模）
  - **C. 旋钮/开关精密控制**（小工作空间、高局部精度）
- 每个任务族分别训练一个类别专家，每个任务执行 **50 次闭环 rollout**，使用固定的任务列表和种子计划。

### 复合任务（Composite Benchmark）
- 使用 RoboCasa365 的 `lifelong_learning_phase2` 设置：**20 种复合任务类型**，每个任务链式包含 2～3 个原子子目标。
- 每个接口在全部 20 种类型上联合训练一个策略，每个任务执行 **25 次闭环 rollout**。
- 额外在复合任务上使用关节角状态表示进行对照实验（动作空间仍为末端执行器 delta）。

### 对比方法
- 无状态基线（No-state, NS）
- 五种单帧接口：SP、VP、AP、SE、FM
- 历史深度对比：对 vp、ap、se、fm 分别扫描 K=1、4、8、16、32、48、64、96
- 槽匹配重复当前状态对照
- 复合任务 EEF 位姿 vs. 关节角状态对照

### 统计方法
- 配对任务自助法（paired task-bootstrap）95% 置信区间；对单一种子使用点估计。

## 6. 主要结论与发现

### RQ1：当前状态是否有用？
- 总体上，当前状态有益：五个接口的宏平均成功率均超过无状态基线（+1.1～+3.1 点），其中 **SP 的增益 57.7% 有统计支持**（95% CI [0.2, 6.1]）。
- **不存在任务无关的最优接口**：
  - 任务族 A（重排）：SP 最优（68.7%，+7.0）。
  - 任务族 B（铰接交互）：VP 最优（68.8%，+6.1），SE、FM 接近。
  - 任务族 C（精密控制）：SE 最优（42.8%，+3.3），VP 反而低于基线（−1.2）。
- 接口间计算成本差异巨大：SP 最昂贵，SE/FM 能以低一个数量级的边际计算达到接近的宏观表现。

### RQ2：状态历史有多大帮助？
- **短历史有益，长历史有害**（非单调趋势）。在原子任务上，K=1→8 通常提升性能，K≥16 后无益甚至显著退化，尤其任务族 C。
- **8 帧是实用的操作点**：在原子和复合任务中均表现稳定，作为默认配方。
- 历史增益来自**真实的时序变化**，而非额外 slot 容量：槽匹配重复当前状态显著低于真实有序历史（复合任务 AP：30.8% vs 39.0%，Δ=+8.2），置信区间排除零。
- 该结论对状态表示（EEF 位姿 vs. 关节角）稳健，两者保持相同定性优势。

### RQ3：状态应注入哪里？
- **单帧（K=1）时，VLM 侧更优**：复合任务中 VP1 显著超过 AP1（34.4% vs 28.2%），关节角状态下亦有同样趋势。
- **短历史（K=8）时，动作侧更优**：AP 从 K=1 到 K=8 的提升最大（复合任务 +10.8 点，EEF 状态；+4.8 点，关节角），而 VP 增益很小甚至为负。
- **设计规则**：“单帧状态注入 VLM，短历史注入动作头”。该规律在两个状态表示、两类任务集上均成立，但注意接近 K=8 时 AP 与 VP 差距可能处于统计噪声带内，为方向性规律而非严格因果排序。

## 7. 优点

- **极强的控制变量**：所有接口在同一个预训练 π0.5 checkpoint 上微调，共享数据、动作表示、学习率与训练预算，排除混杂因素。
- **系统的任务分解**：将 45 个原子任务按控制语义分为三个任务族，避免了单一平均掩盖接口与任务结构的交互效应。
- **巧妙的槽匹配对照**：通过“重复当前状态”控制额外 token 容量，干净地分离了时序内容与条件容量。
- **多维度评测**：原子任务 + 复合任务、两种状态坐标系（EEF/关节角）、多种统计检验（配对 bootstrap、案例研究配对 episode），结论交叉验证充分。
- **附加探针实验**：固定 checkpoint 的介入实验揭示了 VLM 侧状态对多模态注意力/图像表示的影响，以及动作侧状态修正随去噪轨迹累积的机制，为宏观结果提供数据流层面的解释。
- **成本分析透明**：给出理论计算量推导，使性能与效率的权衡可量化。

---

## 8. 不足与局限

- **缺少真实机器人验证**：所有实验均在 RoboCasa365 仿真中进行，结论对真实世界（噪声、动力学差异、感知误差）的推广性未知。
- **状态仅限运动学**：只包含位置、姿态、基座、夹爪等运动学量，未考虑力/力矩、触觉、关节力矩等模态，可能低估本体感觉在接触类任务中的潜力。
- **统计效力有限**：多数结果为单一种子点估计，配对置信区间仅覆盖少数宏观指标；历史扫描未进行多重比较校正，存在假阳性风险。
- **容量差异未完全对齐**：SE/FM 由于训练样本暴露不同，与其说它们与 VP/AP 对比是“同一容量下的注入位置比较”，不如说是完整系统级比较。
- **路由规律的普适性待考**：作者明确声明“单帧进 VLM、短历史进动作”是方向性规律而非严格因果机制；在关节角状态下 K=8 时 AP/VP 差异不可分辨。
- **计算量估计为理论值**：未报告真实的 GPU 训练时间、显存占用或 wall-clock 延迟，实际工程选择还需更多硬件数据。
