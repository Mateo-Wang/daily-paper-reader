## 摘要
视觉-语言-动作（VLA）模型通常通过自回归文本坐标或不透明的动作标记来暴露空间接地，从而在多模态推理与机器人执行之间产生脆弱的接口。我们提出Pointing-VLA，一种基于Embodied-R1构建的类型化隐藏状态空间读出。几何专用头预测归一化点、对象功能接地（OFG）热图以及视觉轨迹，而无需将几何序列化为文本。对于评估的Bridge/WidowX和物理拾取-放置部署，显式执行契约将PICK分配给源条件OFG，将PLACE分配给Pointing，提供直接与阶段对齐的空间目标。Pointing-VLA在Bridge/WidowX上实现了SOTA性能，在启用碰撞的CuRobo执行下，无需Bridge特定微调，在评估的四任务集上平均达到72.9%。Pointing和OFG在原生数据集和跨数据集评估中表现出互补优势。OFG/接触读出可迁移至NORA-1.5，在保持或提高成功率的同时，将记录的控制时间减少20倍以上；类型化头在共享外部测试集上比Embodied-R1文本解码快6.68–6.90倍。当作为π0.5动作策略的空间指导集成时，Pointing-VLA在三种视觉情境下将自主真实机器人成功率从52.7%提升至80.7%。这些结果确立了类型化空间读出作为具身推理与机器人执行之间高效、可检查的接口。

## Abstract
Vision-language-action (VLA) models often expose spatial grounding through autoregressive text coordinates or opaque action tokens, creating brittle interfaces between multimodal reasoning and robot execution. We present Pointing-VLA, a typed hidden-state spatial readout built on Embodied-R1. Geometry-specific heads predict normalized points, object-functional grounding (OFG) heatmaps, and visual trajectories without serializing geometry as text. For the evaluated Bridge/WidowX and physical pick-place deployments, an explicit execution contract assigns PICK to source-conditioned OFG and PLACE to Pointing, providing direct stage-aligned spatial targets. Pointing-VLA achieves SOTA performance on Bridge/WidowX, averaging 72.9\% across the evaluated four-task set without Bridge-specific finetuning under collision-enabled CuRobo execution. Pointing and OFG show complementary strengths across native and cross-dataset evaluations. The OFG/contact readout transfers to NORA-1.5, preserving or improving success while reducing recorded controller time by more than 20$\times$; typed heads are also 6.68--6.90$\times$ faster than Embodied-R1 text decoding on a shared external suite. When integrated as spatial guidance for a $π_{0.5}$ action policy, Pointing-VLA raises autonomous real-robot success from 52.7\% to 80.7\% across three visual contexts. These results establish typed spatial readouts as an efficient, inspectable interface between embodied reasoning and robot execution.

### 1. 论文的核心问题与整体含义（研究动机与背景）

- **核心问题**：现有 VLA（视觉-语言-动作）模型在空间接地（spatial grounding）的输出接口上存在根本性缺陷——它们要么将空间目标序列化为文本坐标（如 `[x,y]`），要么直接输出不透明的动作 token，导致多模态推理与机器人执行之间的接口脆弱、不可检查、且解码开销大。
- **具体痛点**：
  - **文本坐标**：需要模型花费 token 逐位“拼写”数字，评估者需解析字符串回像素坐标，密集的部件级空间证据在执行前即被丢弃；且文本生成可能在语法上合法但空间上错误（如图 1 所示的两个典型失败案例），解析本身成了额外的执行依赖而非接地成功的保证。
  - **动作 token**：虽避免了解析，但隐藏了空间推理的依据，机器人栈或人类审计者无法检查其合理性。
- **核心主张**：具身接地应被视作**类型化接口预测（typed interface prediction）**，而非文本坐标生成。指认点（point）、功能区域（affordance region）、视觉轨迹（trajectory）是相关但**不同几何形态**的目标，应各自以原生几何形态输出，而非经过文本序列化或塌缩为单一分布。该主张受神经科学中“感知-行动双通路”（Goodale & Milner）和“群体读出”（population readout）计算视角启发：下游读出应直接从分布式内部活动中解码空间变量。

### 2. 论文提出的方法论

#### 2.1 核心思想
- 构建 **Pointing-VLA**：以 Embodied-R1 作为共享多模态骨干，在隐藏状态上附加轻量几何专用头，直接读出归一化点、OFG 热图、视觉轨迹三种空间目标，**全程不生成也不解析坐标文本**。

#### 2.2 架构与关键技术细节
- **隐藏状态读出（Hidden-State Spatial Readout）**：
  - 复用同一个骨干架构和 Grounding Adapter 主体，但每个专家（point/OFG/VTG）保留自己的 LoRA、学习查询和 decoder 状态。
  - Adapter 流程：`X_e = W_e H_mm + P_e` → 查询交叉注意力（8 个 grounding queries）→ FFN → 得到固定数量 grounded tokens `G_e` → 全局池化 `g_e`。
  - VTG 专家例外：让学习到的时序查询直接注意完整多模态序列，避免固定 grounding-token 瓶颈。

- **Pointing 解码器**：学习指针查询 `q_pt` 通过交叉注意力选择 grounded 证据，经 LN + 线性投影 + sigmoid 直接输出 `(x_hat, y_hat) ∈ [0,1]^2`，像素坐标通过 `(W-1)·x_hat, (H-1)·y_hat` 换算。
- **OFG 热图解码器**：全局 grounded summary 通过 FiLM 调制视觉塔的 2D 特征图 `F_vis`，再经卷积热图解码器（借鉴 AGD20K）输出 heatmap logits，取峰值作为执行端功能接触点。
- **VTG 轨迹解码器**：T=8 个时序 waypoint 查询依次注意多模态序列，输出归一化图像空间轨迹点。
- **固定 PICK/PLACE 执行契约**：
  - `q_pick` 由指令 + 源描述构造，喂给 OFG 头 → 输出功能接触点（PICK）。
  - `q_place` 由指令 + 目标描述构造，喂给 Pointing 头 → 输出放置坐标（PLACE）。
  - 外部 wrapper 通过标定深度 D、相机内参 K 和相机-机器人变换 `T_r←c` 将图像空间输出映射为机器人坐标系目标。

#### 2.3 训练目标与阶段
- 加权空间目标：`L = λ_pt L_pt + λ_box L_box + λ_ofg L_ofg + λ_vtg L_vtg + λ_aux L_aux`，其中点/轨迹用 SmoothL1，OFG 用 MSE（Gaussian keypoint）或 class-balanced BCE（dense mask）。
- **源条件 OFG 特化**：冻结 Embodied-R1 base、Pointing/VTG 模块和 executor，联合更新 OFG LoRA、共享 Adapter、OFG query 和 heatmap decoder；组合 dense source-mask 重建 + 源-干扰物排序 + 干扰物抑制，使 OFG 在 PICK 读出中直接解析源实例。
- **GRPO 风格连续空间细化**：以策略中心 `μ = p̂`、学习方差 `σ = exp(s)` 采样 `a_i = clip(μ + σ·ε_i, 0, 1)`，根据目标框给出分段奖励和 group-normalized advantage，附加 SmoothL1 监督点、KL 参考项和 σ 正则。
- **三阶段训练**：
  1. 几何预热（Geometry Warm-up）：训练 Adapter + 8 queries + 几何头；
  2. LoRA 特化：仅更新低秩骨干参数；
  3. 任务延续：只更新任务所需子集。

### 6. 论文的主要结论与发现

- **类型化空间读出有效**：在原生接地基准上，Pointing 匹配 Embodied-R1 的稀疏点精度（64.3%），而 OFG 将 Part-Affordance-2K 从 40.9% 提升至 57.3%（+16.4 点）——几何特化显著增强了部件级功能接地。
- **固定 OFG-PICK/Pointing-PLACE 契约最优**：仿真四任务平均成功率达 **72.9%**，比最强替代组合高 14.6 个百分点；Stack 任务 100% 成功率，Eggplant 22/24。
- **源条件 OFG 直接解析 PICK 源选择**：48 个在线案例中源选择全部正确，43/48 完整成功（优于 Attention-PICK 的 40/48）。
- **跨数据集互补性**：Pointing 在 RefCOCO/RoboAff 最强，OFG 在 AGD20K/Part-Affordance-2K 最强——印证了不同接口对应不同几何需求。
- **效率优势显著**：typed heads 较 Embodied-R1 文本解码快 **6.68–6.90 倍**；OFG/contact 读出迁移至 NORA-1.5 后控制时间减少 **20 倍以上**。
- **可增强现有动作策略**：作为 π0.5 的空间指导，真实机器人成功率从 **52.7% → 80.7%**（+28 点），失败主要集中在执行转移阶段而非空间接地阶段。

### 7. 优点

- **问题定义清晰**：将“空间输出接口”视为 VLA 系统的独立设计维度，而非隐含在动作 token 或文本中的附属物，填补了现有研究的空白。
- **方法机制与理论支撑统一**：从神经科学的“感知-行动通路”和“群体读出”获得灵感，方法设计与动机自洽，不是简单的工程拼凑。
- **严格的实验协议**：
  - 统一 PIM/PIB 评分，跨数据集比较在各接口同一样本上完成；
  - 所有对比共享相同 episode 身份；
  - 仿真部署启用碰撞检测（CuRobo），防止“动态投掷式”虚假成功；
  - 真实机器人 50 次/场景的试验量在同类工作中属于较高水平。
- **消融覆盖全面**：从查询数、LoRA rank、细化方式到接口组合逐项验证，并识别出性能由空间读出设计而非参数量单独决定。
- **跨骨干与真实部署证据链完整**：NORA-1.5 转移验证了读出头的通用性，π0.5 + Pointing-VLA 真机实验验证了与现有动作策略的即插即用兼容性。

### 8. 不足与局限

- **样本量偏小**：Bridge/WidowX 每任务仅 24 episodes，跨数据集诊断也有较多划分细节未在正文展开；统计显著性检验（置信区间、方差分析）未报告。
- **控制时间指标的解释空间**：NORA-1.5 的“记录控制器时间减少 20 倍”是控制器耗时而非总任务耗时，真实效率增益可能被高估；虽然作为接口效率指标合理，但不应直接类比为端到端加速。
- **任务多样性有限**：真实机器人仅验证单对象（白色复合材料部件）+ 单一托盘放置场景，三种视觉情境仅干扰物颜色差异，未覆盖多对象、非刚体、动态环境等挑战。
- **跨本体泛化未深入**：虽然验证了 NORA-1.5 骨干迁移，但未测试学习头本身在不同机械臂形态间的直接迁移；图像空间读出依赖标定深度和 `T_r←c` 变换，对未标定或深度退化场景的鲁棒性未知。
- **文本解码对比范围窄**：运行时对比仅针对 Embodied-R1 一种文本生成模型，未与其他 VLA 文本坐标生成系统（如 RoboPoint 的逐 token 解码）进行系统对比；且坐标归一化策略、prompt 设计可能影响文本解码的公平性。
- **固定契约的局限**：OFG→PICK / Pointing→PLACE 是人工设定的确定性分配，依赖任务结构先验；对于需要多步迭代、动态重规划或非拾放类任务的泛化性未充分探讨。
- **Spoon-on-towel 任务性能波动明显**（50% vs 其它任务 91.7–100%），论文自指为“任务依赖差异”，但也表明当前开放式接口在特定结构上的短板；论文将其归因于执行闭环缺失，实际机制尚未完全厘清。
- **训练成本未披露**：未报告 LoRA 特化、GRPO 细化等阶段的具体训练时长与资源消耗，不利于复现和公平的能效对比。
