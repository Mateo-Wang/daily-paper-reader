## 摘要
视觉-语言-动作（VLA）模型在机器人操作领域日益展现出应用潜力，但其实际部署仍受限于高推理延迟和不稳定的异步执行。这一挑战在基于流匹配的VLA模型中尤为突出，因为动作解码需要多次迭代步骤，并取决于VLM上下文。尽管高效推理方法能提高控制频率，异步方法能减少执行空闲时间，但现有方法往往无法同时实现低延迟推理和准确、时间一致的异步执行。我们提出了\textbf{FlashVLA}，一种流式动作解码框架，以统一的形式解决这两个挑战。FlashVLA维护一个包含多个不同噪声水平块（chunk）的流式动作缓冲区，并使用分块因果注意力（chunk-wise causal attention）对它们进行解码。这种设计使FlashVLA能够在每个推理步骤产生一个可执行的动作块。此外，其分块自回归形式隐含地保持动作连续性，从而无需额外的未来状态条件即可实现平滑的异步执行。在广泛的模拟和真实世界实验中，FlashVLA在保持强任务性能的同时大幅提高了推理速度。在单GPU上可实现$\geq$30\,Hz的控制频率，并在实际部署中具有平滑的异步推理能力。

## Abstract
Vision-Language-Action (VLA) models are increasingly promising for robotic manipulation, yet their real-world deployment remains bottlenecked by high inference latency and unstable asynchronous execution. This challenge is particularly pronounced in flow-matching-based VLA models, where action decoding requires multiple iterative steps conditioned on the VLM context. While efficient inference methods improve control frequency and asynchronous methods reduce execution idle time, existing approaches often fail to jointly achieve low-latency inference and accurate, temporally consistent asynchronous execution. We introduce \textbf{FlashVLA}, a streaming action decoding framework that addresses both challenges in a unified formulation. FlashVLA maintains a streaming action buffer with multiple chunks at different noise levels and decodes them using chunk-wise causal attention. This design allows FlashVLA to produce one executable action chunk per inference step. Moreover, its chunk-wise autoregressive formulation implicitly preserves action continuity, enabling smooth asynchronous execution without extra future-state conditioning. Across extensive simulated and real-world experiments, FlashVLA substantially improves inference speed while maintaining strong task performance. It can achieve $\geq$30\,Hz control frequency on a single GPU with smooth asynchronous inference in real-world deployment.

## 1. 核心问题与整体含义

- **研究动机**：视觉-语言-动作（VLA）模型在机器人操作中表现出色，但其实际部署受限于**高推理延迟**和**不稳定的异步执行**。尤其是基于流匹配（flow matching）的VLA模型（如π0.5），动作解码需要多步迭代去噪，导致单步推理时间过长。
- **现有矛盾**：
  - 同步推理虽然保持观测与动作的时间对齐，但会在每个动作块边界产生停顿；
  - 异步推理虽能重叠预测与执行，但依赖过时观测，预测与机器人实际状态存在时间错配（mismatch），且前瞻距离越大，错配越严重。
  - 已有工作要么只优化单步延迟（如轻量架构、压缩、token剪枝、少步蒸馏），要么通过未来状态预测/动作条件化等额外模块修补异步错配，但均未能同时解决“低延迟”和“时序一致性”两个挑战。
- **核心观点**：上述两类问题的共同根源在于——传统流匹配VLA将每个动作块**孤立解码**（从纯噪声开始，仅依赖当前观测，与已在执行中的块无关联）。孤立解码既导致所有去噪步骤集中在单次解码中（延迟成本），又使新块不了解其即将加入的轨迹（错配成本）。
- **FlashVLA的整体含义**：通过“联合解码动作块”这一统一结构改变，同时消除延迟瓶颈和异步错配，为VLA高效异步部署提供新范式。

## 2. 方法论

### 2.1 核心思想
- 受长视频生成中流式块级扩散（streaming chunk-wise diffusion）启发，FlashVLA维持一个**动作块缓冲区**，缓冲区内各块处于**阶梯式噪声水平**，并通过**块级因果注意力**联合去噪。
- 每个前向传播同时推进缓冲区中所有块一步，经过预热后，每个推理步骤输出一个可执行动作块。每个块虽然仍经过全部N个去噪步骤，但这些步骤被分摊到N个不同推理时刻，从而大幅降低单步延迟。

### 2.2 技术细节
- **分块自回归公式**：
  - 传统流匹配：对动作块 $a_t = \{a_t, \dots, a_{t+H-1}\}$，从高斯噪声 $x_1$ 迭代去噪，学习速度场 $v_\theta(x_\tau, \tau | o_t)$，满足
    $$x_\tau = (1-\tau)a_t + \tau z,\quad \frac{dx_\tau}{d\tau} = z - a_t = v_\theta(x_\tau, \tau | o_t)$$
  - FlashVLA维护N个噪声水平逐渐增加的块：
    $$B_t = [x^{(1)}_{\tau_1}, x^{(2)}_{\tau_2}, \dots, x^{(N)}_{\tau_N}],\quad \tau_1 < \tau_2 < \dots < \tau_N$$
    其中 $\tau_i = 0.001 + 0.999 \frac{i-1+u_i}{N}$，$u_i \sim \text{Beta}(1.5, 1.0)$。
  - 噪声水平与执行顺序对齐：噪声最低（几乎干净）的块最先执行，噪声最高（纯噪声）的块最后执行。
  - 应用**块级因果掩码**：较噪（较未来）的块可以关注较干净（较近执行）的块，反之则不允许。这保证了信息沿时间向前流动，同时隐式地让未来动作受已规划轨迹影响，无需显式未来状态预测器。
- **流式推理算法**：
  - **冷启动**：在Episode开始时，缓冲区为空，用N-1个填充块和一个高斯样本初始化，执行N-1次前向传播填充缓冲区，机器人执行安全默认动作（如保持静止）。该开销每Episode支付一次，在后续 rollout 中摊销。
  - **稳态流式执行**：每个推理步骤推进所有块、弹出最干净的块执行、其余块前移、在尾部追加新的纯噪声块。算法见正文Algorithm 1。
  - **系统级优化**：采用CUDA Graph编译、线性层打包、PyTorch max-autotune等，减少kernel启动开销，实现非阻塞异步执行。
- **多缓冲区联合微调（Multi-Buffer Joint Fine-tuning）**：
  - 预训练VLA针对孤立块解码训练，未见过部分填充的缓冲区。为适配流式范式，需要让模型学会处理所有可能的缓冲区配置。
  - 将N种冷启动/稳态配置打包到同一个训练样本中（共享同一观测ot，但用注意力掩码隔离不同缓冲区），避免重复编码观测，显著提高微调效率。
  - 联合训练损失为所有缓冲区配置的流匹配损失之和：
    $$\mathcal{L}_{\text{joint}} = \sum_{j=1}^{N}\sum_{i=1}^{j} \mathbb{E}_{\tau_i,z_i}\left[\left\| v_\theta(x^{(i)}_{\tau_i}, \tau_i | o_t, B_t^{(j)}) - (z_i - a^{(i)}) \right\|_2^2\right]$$
  - 该损失同时覆盖冷启动和稳态流式行为。

## 7. 优点

- **统一解决两大挑战**：用一个结构设计同时降低延迟并恢复异步连续性，思想简洁、有洞察力。

- **隐式异步条件化**：通过块级因果注意力，未来块可关注近执行块，天然嵌入轨迹连续性，免去显式未来状态预测器或额外监督模块。

## 8. 不足与局限

- **冷启动开销**：每个Episode开始需N-1次预热前向传播，机器人需执行安全默认动作，在短时任务中该成本占比更明显。
- **依赖预训练模型的独立块目标**：FlashVLA是在预训练VLA基础上微调，未从零训练以完全适应流式公式，可能限制潜在增益。作者也指出“从零预训练”是自然下一步。
- **训练稳定性问题**：流式公式改变了动作专家的时间步条件分布，微调时偶尔出现梯度爆炸，某些数据集（如RoboTwin 2.0大规模多任务）需要重新初始化归一化层并从头训练，增加训练复杂性。
- **跨架构迁移需额外适配**：对于SmolVLA等未使用FiLM条件的架构，需要额外添加时间MLP和FiLM层。
- **真实世界验证规模有限**：仅三项任务、每项15次试验（有效完成时间只统计成功轨迹），统计功效受限；不同任务间难度和硬件差异可能影响普适结论。
- **仿真和真实世界的速度差异**：RoboTwin 2.0的每步时间被渲染和通信主导，FlashVLA在真实系统中的端到端加速不如仿真显著（1.08~1.10×）。
- **block大小/长度选择敏感**：最佳配置需要总缓冲跨度接近预训练模型原生动作块长度，在较短任务中可能不匹配。
