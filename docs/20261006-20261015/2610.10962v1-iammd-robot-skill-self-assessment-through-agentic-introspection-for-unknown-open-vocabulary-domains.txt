iAm.md: Robot Skill Self-Assessment through Agentic
Introspection for Unknown Open-Vocabulary Domains
Vincenzo Guarino1,*, Emanuele Musumeci1, Vincenzo Suriani1 and Daniele Nardi1
1Department of Computer, Control and Management Engineering “Antonio Ruberti”, Sapienza University of Rome, Via Ariosto
25, 00185 Rome, Italy
Abstract
Agentic AI based on Large Language Model generalization capabilities offers a wide range of potential appli-
cations, including planning for embodied tasks. For example, embodied agents based on Foundation models
can generate plausible plans in autonomous robotics scenarios. Due to limited context windows or hallucina-
tory phenomena in the next-token prediction formulation, behaviors may be generated without establishing
whether the deployed robot and the observed environment actually support the requested operation, in what
we call a "grounding failure". Thanks to the recent improvements in reasoning capabilities of foundation models,
autonomous robot behavior generation problem can be formulated as a code generation problem. We present
iAm.md, a Markdown standard and generation framework, that allows anchoring this process in complementary
forms of deployment evidence. Through open-vocabulary semantic mapping, we combine local vision-language
detections and object segmentation and refer them to persistent object records in this intermediate standard-
ized representation, allowing agentic introspection. We then study this new technique on a simulated TIAGo,
on navigation-and-manipulation tasks, showing how this standardized representation jointly supports skill self-
assessment and executable task generalization.
Keywords
Robot skill self-assessment, agentic introspection, open-vocabulary semantic mapping, foundation-model
agents, robot code generation, ROS 2
1. Introduction
Translating a Natural Language (NL) task request into physical robot behavior typically requires a
closed representation of the task and operating environment: neuro-symbolic planning makes plan
validity conditional on the quality of a provided abstraction of the world state and actions [1, 2, 3]. As
robots move toward open environments, prompt engineering is an increasingly important step of plan
and executable code generation [4, 5], but this capacity creates a grounding problem: a language model
may complete an underspecified request with synthetic knowledge even when the necessary evidence
has not been observed [6], and generated action sequences can violate the preconditions of the actions
they invoke [7]. Once connected to robot tools, an unsupported assumption becomes a physical action,
which can lead to obvious safety and ethical issues.
In this way, a generated program may refer to an unobserved object, or it may call for an opera-
tion that the deployed platform does not support. Scene grounding alone does not resolve the second
problem, since a plan reasonable for one robot may fail on another. Robot self-assessment frames the
missing judgment as the ability to "predict, estimate, or measure how well it can perform a task in
a given context and environment" [8]. We investigate to what extent an embodied foundation model
agent operating in an unknown open-vocabulary domain can use persistent scene memory and a struc-
tured robot self-description to perform skill self-assessment and produce executable plans. Here agen-
tic introspection means the agent is capable of inspecting the representations available inside its own
planning process before committing to generated code. Our contributions are: (i) an open-vocabulary

2. Related Work
Hierarchical 3D scene graphs (Kimera [9], Hydra [10]) and dense vision-language feature maps
(VLMaps [11], ConceptFusion [12]) accumulate persistent spatial structure but do not maintain robot-
specific execution evidence. Language-conditioned code-generation methods (SayCan [13], Code as
Policies [14], ProgPrompt [15]) compose developer-provided APIs but assume feasible instructions
and pre-authored platform documentation; feasibility-assessment methods (PlanBench [7], Code-
Botler [16], KnowNo [17]) require a complete action model rarely available for a configured robot.
Robot knowledge frameworks [18, 19, 20] relate tasks to capabilities through data entered before an
episode. Closest to our work, EMPOWER-ADF [21] grounds task entities against a NL robot descrip-
tion but selects from a fixed action vocabulary without physical execution. We instead derive the robot
description from the deployment itself and use it, with live interface evidence, to write task-specific
code.
3. Methodology
An embodied code generation system places a tool-calling foundation-model agent between a task re-
quest and the deployed robot. Persistent robot facts enter the agent context through iAm.md, whereas
the current pose and camera observation describe the state in which the request must be executed.
One general command tool connects this context to the live ROS 2 environment [22], allowing the
agent to observe the execution state, write executable programs, and run them in the deployment that
supplied the supporting evidence. The semantic map supplies object identities and spatial support
through ROS 2 topics and a serialized snapshot, so generated programs resolve task targets without
placing transient observations in the persistent robot description. Figure 1 summarizes these evidence
paths and the execution loop that connects the generated program to the deployed robot.

iAm.md: embodiment evidence.
iAm.md is a standard for describing the persistent embodiment
of a configured robot deployment in plain text that a foundation-model agent can read in context.
A conforming document follows a fixed schema from identity and embodiment summary, through
the URDF-derived physical structure, actuation, and sensing, to the higher-level software functions
exposed by the robot stack and the unknowns that remain after generation. Every block carries ex-
plicit cardinality, a value that cannot be defensibly established is recorded as unknown in place, and
software-function records separate the acceptance criteria of a command interface from the physical
outcome of the commanded operation. An instance is generated once per deployment from the URDF,
augmented with the live ROS 2 graph and configuration artifacts for otherwise-unobservable inter-
faces. The TIAGo [26] instance used here records its kinematic structure, navigation and gripper en-
velopes, controller bindings, and Navigation2 [27]/MoveIt function records. The acceptance/outcome
separation appears concretely in the gripper records: a successful gripper trajectory result establishes
only that controller tolerances were met, and grasp retention is listed among the unknowns because
the deployed configuration includes no sensor that could establish it.
Agentic introspection and robot code execution.
Each NL request is one execution episode. The
startup prompt defines the command-tool protocol and embeds the generated iAm.md between explicit
delimiters. The agent inspects the ROS 2 graph and interface schemas through the same command tool
it uses to act, so interface availability is established from the deployed system during the episode. Skill
self-assessment runs inside the agent loop: the agent relates the request to observed objects, then
checks the robot description and live interfaces needed to realize the operation/navigation needs the
object location and navigation interface, whereas manipulation additionally requires the manipula-
tor and gripper contracts. When evidence supports the operation the agent proceeds to observation,
program construction, or a physical command; otherwise a structured outcome records a blocked re-
sult. Introspection continues during execution, because observed behavior can expose an unsupported
assumption and prompt a revision of the program.


4. Experimental Results
4.1. Semantic-Map Evaluation
Twelve objects in a simulated scene were independently annotated as labelled spheres in the map frame
through an interactive RViz interface. An estimated record is compatible with an annotation when its
centroid lies inside the sphere and its label matches; a maximum one-to-one bipartite matching over
compatible pairs yields object-level Found (fraction of annotations matched) and Correct (fraction of
estimates matched) scores, following Hydra [10]. The matching selected 12 pairs from 12 annotations
and 13 estimated records: every annotated object was recovered (Found = 100%), and the single un-
matched record was a duplicate estimate (Correct = 92.31%), localizing the observed error to duplicate
consolidation during map updates and merges.
4.2. Agent-Produced Tool Evaluation
The agent evaluation isolates the contribution of iAm.md by varying only the persistent robot knowl-
edge available during tool construction. Both conditions run the same embodied coding agent, a Deep-

and both receive the same fixed request together with a distilled NL specification of the navigation-
and-manipulation tool to be built. The specification was distilled from a reference implementation de-
veloped with Claude Fable 5 on the same platform, with every deployment fact removed, so the agent
must recover the robot connection itself, and iAm.md is placed only in the documented workspace.
A phase ends when the submitted tool passes independent verification (a simulator reset, unattended
execution, and a static audit rejecting tools that do not use robot depth data), or when the agent reaches
a 110-minute budget after at most four attempts.
Phase 1: construction.
For “grasp a drink can and place it on a sofa”, the documented agent produced
a tool that passed verification after a simulator reset in 50.4 minutes, using 103 model calls and 8.50
million input tokens. The agent without iAm.md reached the 110-minute budget (186 model calls, 20.32
million input tokens) without a verified grasp or a completed task (Table 1A). The gap appeared at the
earliest milestones: the documented agent wrote a first tool version after 4.8 minutes and reached a
verified grasp approach after 7.8 minutes, against 8.2 and 26.4 minutes without the description, and
it first verified a grasp after 25.7 minutes while the other agent obtained none within budget (4/10
versus 0/19 successful grasp attempts). Lacking the recorded embodiment, the undocumented agent
calibrated the gripper through execution and incurred 13 initial inverse-kinematics failures, recovering
constraints that iAm.md supplies directly; it also made 23 live-discovery calls, against 14 discovery calls
and five iAm.md reads for the documented agent.
Phase 2: reuse.
Retaining the documented agent’s state and tool, the request changed to move a cube
to the opposite side of a table, a different object geometry and placement relation. The agent raised the
torso, verified clearance, and executed the verified joint configuration, avoiding an elbow-wrapping
IK switch during retreat. To represent the other side, it extended the tool interface with a map-frame
approach direction rather than a cube-specific behavior. The plan passed its first verification after a
simulator reset. Reuse required only three additional discovery calls and no further iAm.md reads (Ta-
ble 1B); the changed geometry nonetheless propagated into grasp planning and placement, requiring
49 tool edits and 34 reported step failures. Retaining the command vocabulary while extending the
generic kinematic and directional mechanisms constitutes few-shot generalization.

5. Conclusions and Future Work
We showed that an embodied foundation-model agent can combine persistent scene memory, a robot
self-description, and live ROS 2 observations to assess and realize NL tasks in an open-vocabulary
domain. The semantic map recovered all twelve annotated objects with one duplicate record. In a
controlled comparison, access to iAm.md was associated with lower construction cost and verified
completion: the documented agent produced a verified tool in 50.4 minutes, versus the 110-minute
budget without a verified grasp for the undocumented agent, expending roughly twice the calls and
tokens. Retaining that tool, the agent extended it to a second task with different object geometry
without rereading iAm.md-evidence of few-shot generalization, from a single simulated run. Future
work will evaluate iAm.md generation across embodiments and add an independent safety boundary
validating trajectories before actuation on physical robots.
