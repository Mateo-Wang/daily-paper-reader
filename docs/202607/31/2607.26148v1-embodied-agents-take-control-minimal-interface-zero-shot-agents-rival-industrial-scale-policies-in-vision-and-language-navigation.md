## 摘要
自主具身智能体必须在多步骤中维持一个涉及感知、行动、验证和自我纠正的长时间决策循环。当前系统通过任务特定工作流或具身策略来维持这一循环。我们研究第三种形式，即智能体具身控制，其中通用智能体自行持有循环。以零样本导航为受控测试平台，我们仅使用单目RGB摄像头和离散动作评估了三种软件工程智能体框架。在这种严格最小条件下，复制的默认努力配置达到70.7±3.5%的成功率（opus-5，三次运行的平均值），而fable-5在最大努力下达到78%。当训练好的路点工具与原始动作一起作为可选能力暴露时，混合fable-5智能体在默认努力下达到76.7±0.6%的成功率，使用了一半的环境步骤和少于最大努力原始运行四分之一的墙钟时间。受控干预显示，能力主要集中于模型：模型选择强烈影响成功率，框架效应是描述性的，强制路点接口有助于较弱模型但可能阻碍较强模型。然而，在更长视界任务上性能急剧下降，而延迟和上下文增长限制了持续运行。这些结果表明，智能体控制已在零样本导航中具有竞争力，模型、框架和接口为自主具身智能体提供了互补路径。

## Abstract
Autonomous embodied agents must sustain a long decision-making loop that involves perceiving, acting, verifying, and self-correcting over many steps. Current systems sustain this loop through task-specific workflows or embodied policies. We study a third form, agentic embodied control, in which a general-purpose agent holds the loop itself. Using zero-shot navigation as a controlled testbed, we evaluate three software-engineering agent harnesses given only a monocular RGB camera and discrete actions. Under this strictly minimal condition, replicated default-effort configurations reach 70.7$\pm$3.5% success (opus-5, mean over three runs), and fable-5 reaches 78% at maximum effort. When a trained waypoint tool is exposed alongside primitives as an optional capability, the hybrid fable-5 agent reaches 76.7$\pm$0.6% at default effort, using half the environment steps and less than one quarter of the wall time of the maximum-effort primitive run. Controlled interventions show that capability is primarily model-centered: model choice strongly changes success, harness effects are descriptive, and a forced waypoint interface helps weaker models but can hinder stronger ones. Performance nevertheless falls sharply on longer-horizon tasks, while latency and context growth limit sustained operation. These results show that agentic control is already competitive in zero-shot navigation and that models, harnesses, and interfaces offer complementary paths toward autonomous embodied agents.

## 一、核心问题与整体含义

**研究动机与背景**
- 自主具身智能体需在长时间交互中维持"感知—行动—验证—自我纠正"的决策闭环
- 现有两大技术路径各有限制：
  - **策略路径**（如 NaVid、Qwen-RobotNav）：将导航能力内化于模型权重中，由外部环境循环驱动，需大规模导航数据训练
  - **工作流路径**（如 NavGPT、MapGPT、SmartWay）：冻结通用模型，由人编写的管道代码提供空间表示与规划结构，模型只是其中一环
- 近期工业级"双脑"系统（如 ABot-N1、InternVLA-N1）虽将慢速推理与快速动作专家耦合，但控制流仍由人预设
- 本文提出**第三种范式——智能体具身控制（Agentic Embodied Control）**：由通用模型自身主导交互循环，决定何时观察、执行何种动作、如何纠错、何时停止

**整体含义**
- 用最简接口（单目 RGB + 四个离散动作）的零样本导航测试，验证"模型能否控制具身交互循环"这一根本问题
- 若通用软件工程 agent harness + 前沿 VLM 已达工业级策略性能，则导航专用脚手架不再是零样本导航的必要条件

## 二、方法论

**核心思想**
- 用**软件工程 agent harness**（非导航专用）替代一切导航脚手架
- 模型持有高层控制权：自主决定观察时机、动作序列、路径修正和终止条件
- 将系统拆分为三个正交因素——**模型（Model）、框架（Harness）、接口（Interface）**——分别考察各自贡献

**最小感知—动作接口**
- `observe()`：返回单张 512×512 前视 RGB 帧（HFOV=90°），不推进环境
- `step(actions)`：执行离散动作序列，仅含四个 Habitat 原语：
  - `FORWARD`：前进 0.25 m
  - `LEFT` / `RIGHT`：旋转 15°
  - `STOP`：终止回合
- **严格排除**：深度、全景、位姿、里程计、地图、碰撞反馈、路点候选、显式记忆
- 工具仅报告已执行原语数和剩余预算，无图像/碰撞信号
- 模型必须通过重复调用 `observe()` 感知动作效果

**三种 Harness（均面向软件工程）**
- `mini-swe-agent`：SWE-bench bash-only 排行榜的最小参考框架
- `Claude Agent SDK`：Anthropic 官方智能体框架
- `Codex CLI`：OpenAI 本地软件智能体框架

**混合接口（Hybrid）**
- 同时暴露原始动作（primitives）和训练好的路点预测器（waypoint）作为可选工具
- 由模型自主决定何时用粗粒度路点、何时用细粒度原语

**系统提示词与流程**
- 固定单文件提示词，所有 harness 逐字节一致
- 每 episode 新开会话，无跨 episode 状态

## 六、主要结论与发现

1. **最小接口已达工业级性能范围**
   - 默认努力：opus-5 达 70.7±3.5% SR，fable-5 达 68.3±1.5% SR
   - 最大努力：fable-5 达 78% SR（SPL 65.27）
   - 超过 AgenticNav（55 SR，带地图、记忆、搜索），接近 Qwen-RobotNav（72 SR，训练于百万级样本）

2. **能力以模型为中心，但不是模型独有**
   - 固定 harness 与接口，模型选择跨越 5–72 SR（全研究最宽范围）
   - 框架效应仅 2–7 SR，且方向不一致，属描述性差异
   - 推理努力提升效果模型特异：仅 fable-5 显著受益（+9.7 SR），其他模型无一致方向

3. **接口强制 vs 可选是关键**
   - 强制 waypoint 接口补偿弱模型（小 Qwen 提升 37–38 SR）但几乎不帮助强模型（fable-5 仅 +0.7，opus-5 仅 +1.3）
   - VLNVerse 上 waypoint 甚至**反向损害**强模型（SR 降 4–6，CR 升 4–6 倍）
   - **混合接口**（waypoint 作可选工具）：fable-5 达 76.7±0.6% SR，超过任一固定接口，NE 最佳，且比最大努力纯原语少一半环境步骤、少四分之三墙钟时间

4. **长视界是硬瓶颈**
   - RxR-CE 上 SR 降至 26（原语）与 39（waypoint），比 R2R-CE 低 30–49 点
   - 上下文末轮中位数从 22.6k 增至 49.2k tokens，墙钟时间翻倍以上

5. **失败是沉默而自信的**
   - 25 个失败中 23 个自愿 STOP，22 个明确声称成功；声称的置信度与最终距目标距离（3.1–44.6m）无关
   - 仅 4/25 曾进入 3m 成功区域——属"路线级"早期分叉错误
   - **核心认知失败模式：自我诊断但不自我纠正**——至少 10 个 episode 推理中逐字写出正确怀疑，却仍提交错误终点
   - 类别：错误指示物/分支（12）、停止决策失败（6）、失控搜索（4）、几何/模拟器陷阱（3）

6. **物理部署：推理迁移，身体缺席**
   - 逻辑条件导航、细粒度人物区分、多段路线状态保持均成功
   - 但身体感知缺乏（转弯时未为机身留余量而卡住）、执行报告不可靠（请求即"已执行"）、无持久空间记忆（跨视角计数、相似目标区分失败）

## 七、优点

1. **概念创新**：明确提出"智能体具身控制"作为独立于策略与工作流的第三种范式，并以"谁控制循环"而非"有无 LLM"为判据
2. **最小接口的极致诊断性**：仅单目 RGB + 四个离散动作，排除深度、位姿、地图、碰撞反馈等一切导航先验，干净地暴露模型的原始具身决策能力
3. **严格的三轴分离消融**：模型、框架、接口逐一变化，避免将系统差异混为一谈
4. **"可选优于强制"的深刻洞察**：混合接口实验表明，设计者放弃选择权比增加脚手架更关键——训练模块在智能体控制下被自主调用时价值最大
5. **诚实的失败分析**：25 个失败 episodes 全部逐帧审计，分类互斥，引用原始推理文本，展示了"自我诊断而不自我纠正"的机制，远超常见论文的"失败 = 1-2 个例子"的水准
6. **物理机器人验证**：从模拟到真实四足机器人迁移，并具体指出推理迁移成功与身体感知欠缺的分界线
7. **实验注册制度**：冻结配置、禁止命令行列覆盖，保证可复现性

## 八、不足与局限

1. **长视界能力不足，未能自洽**
   - 作者自认 R2R-CE 的成功是"短视界结果"；RxR-CE 上大幅下降，未提供有效解决方案
   - 上下文无界增长、延迟高企使持续运行不切实际（中位 206 秒/episode）

2. **比较公平性受限**
   - 零样本结果在 rand100 子集
