## 摘要
驾驶决策既取决于关注何处，也取决于如何对所见内容采取行动。有效的驾驶推理必须确定哪些物体重要、它们位于何处，以及它们如何为预期行动提供信息。基于文本的推理依据可以描述驾驶响应，却使其与具体视觉证据的对应关系保持隐含。视觉焦点通过识别场景中什么重要以及它位于何处，为这种联系提供了具体的起点。我们提出 FocusDrive，一个围绕显式视觉焦点组织端到端规划的结构化多模态推理框架。它将与决策相关物体的描述与图像块引用配对，把显式视觉焦点引入生成驾驶规划和轨迹的推理中。我们首先通过驾驶员注视预测评估这种焦点表示，然后利用现有 NAVSIM 训练场景中的驾驶焦点标注，研究其在规划推理中的作用。在 W3DA 和 NAVSIM 上的实验展示了具有竞争力的注视预测和端到端规划性能，其中 FocusDrive 优于基于文本的思维链。这些结果支持视觉焦点作为场景理解与驾驶行动之间的有效纽带。

## Abstract
Driving decisions depend on both where to focus and how to act on what is seen. Effective driving reasoning must establish which objects matter, where they are, and how they inform the intended action. Text-based rationales can describe a driving response while leaving its correspondence to specific visual evidence implicit. Visual focus provides a concrete starting point for this connection by identifying what matters in the scene and where it is. We propose FocusDrive, a structured multimodal reasoning framework that organizes end-to-end planning around explicit visual focus. It pairs descriptions of decision-relevant objects with image-patch references, bringing explicit visual focus into the reasoning that generates driving plans and trajectories. We first assess this focus representation through driver gaze prediction, then investigate its role in planning reasoning using driving-focus annotations within existing NAVSIM training scenes. Experiments on W3DA and NAVSIM demonstrate competitive gaze prediction and end-to-end planning performance, with FocusDrive improving over text-based chain-of-thought. These results support visual focus as an effective link between scene understanding and driving action.

## 2. 方法论

### 2.1 核心思想

- 提出 **FocusDrive**：一种结构化的多模态思维链（CoT）框架，围绕"显式视觉焦点"组织驾驶推理。
- 推理序列被组织为三段式：
  **[物体描述 d_o, 图像 patch 引用 v_j]（视觉焦点） → a（动作计划） → w（未来轨迹文本）**
- 使用分隔符 `<focus>`、`<plan>`、`<answer>`；轨迹以纯文本数值形式输出 8 个航点（每 0.5 秒一个，共 4 秒）。

### 2.2 视觉焦点的表示（图像 patch 引用）

- 采用 **PaDT 的动态视觉引用机制**：视觉骨干输出空间嵌入 $E(I)=[e_1,\dots,e_N]^\top \in \mathbb{R}^{N\times d}$，每个网格单元称为一个 image patch。
- **视觉引用投影器**：先做 LayerNorm，再加低秩残差映射（两层无偏置线性层，瓶颈宽度 $r=64$）：
  $\bar e_j=\mathrm{LN}(e_j),\quad p_j=\bar e_j + W_{up}W_{down}\bar e_j$
  得到原型矩阵 $P(I)=[p_1,\dots,p_N]^\top$。每个原型**既是输出候选，也是该引用 token 的输入嵌入**。
- **统一输出头**：将文本词表与图像相关引用集合并归一化，在同一 softmax 中打分：
  $\ell_t=[W_{text}h_t;\, P(I)h_t]$，$p_\theta(y_t|C,y_{<t})=\mathrm{softmax}(\ell_t)$
  文本 token 保留原有词嵌入，引用 token 使用当前图像的 patch 原型作为输入嵌入。

### 2.3 从视觉引用到注视预测

- 在引用 token 之前的解码位置 $t^\star$，取 VLM 末层隐状态 $h_{t^\star}$，与原型矩阵相乘得到 patch 分数 $z_{t^\star}=P(I)h_{t^\star}\in\mathbb{R}^N$。
- **Gaze Adapter**：对 $z$ 做跨 patch 的 z-score 归一化 → 重塑到 patch 网格 → 5 层卷积 + 双线性上采样 + Sigmoid + 高斯模糊（11×11, σ=2）→ 稠密注视热力图。
- 训练目标：语言建模损失 + 注视损失（BCE + KL 散度），$\lambda_g=3$、$\lambda_{KL}=0.5$；推理时只做一次前向即可出图，无需提供真值引用或注意力解释。

### 2.4 从视觉焦点到端到端规划

- **阶段一：视觉引用 token（VRT）预热**（2 epoch）
  - 在 Navtrain 上构造更广的物体引用标注（物体描述 + 相对位置 + 对应 patch），每个 completion 含多个物体描述与引用，**不含动作计划与航点目标**。
- **阶段二：规划 SFT**（3 epoch）
  - 使用 token 级交叉熵；有焦点标注的场景监督焦点片段 + 计划 + 航点，无标注场景仍监督计划与轨迹。
- **阶段三：GRPO 强化微调**
  - 对每个场景采样 $G=16$ 个 completion，解析航点得到候选轨迹，奖励 $r_i=\mathrm{PDMS}(\tau_i;x)$。
  - 组内相对优势 $A_i=(r_i-\bar r)/(\sigma_r+\delta)$；损失为策略项 + KL 正则（$\beta=0.04$，参考策略为冻结的 SFT 模型）。
  - 奖励覆盖碰撞避免、道路合规、TTC、舒适性与通行效率；奖励标准差低于 0.05 的场景组被排除更新。

### 2.5 驾驶焦点标注流程

- 三阶段：**物理风险筛选（TTC、安全场、交互风险） + VLM（Qwen3.7-Plus）候选筛选 → 人工复核选择最终焦点并标注位置 → 映射到 34×60 patch 网格**。
- 人工负责选择图像位置、修订物体类别与描述、剔除错误标注；VLM 仅提出候选。
- 仅标注 Navtrain 的 **13.1%** 场景，其余 86.9% 仍提供计划与轨迹监督；Navtest 不做标注（仅用于评测）。
- 标注分布：车辆 84.43%、交通灯 7.18%、停车标志 5.32%、行人 2.92%、自行车 0.10%、其他 0.04%；焦点场景中 89.2% 的计划涉及减速。

## 6. 主要结论与发现

- **注视预测**：FocusDrive 在 Normal、Safety、Accident 三类场景中取得最优的 KLdiv、CC 与 AUC 结果，Normal 与 Accident 的 SIM 也最高；在安全关键场景中对 DualGaze-VLM 的相关系数提升最大，说明该表示在困难情境下定位驾驶员焦点的能力较强。
- **端到端规划**：FocusDrive（RL）达到 **91.1 PDMS 与 91.1 EPDMS**，在所列显式 CoT 规划器中领先；NC（99.3）与 TTC（97.7/98.9）表现突出，与标注侧重车辆交互和交通控制线索相一致。
- **相对文本 CoT 的提升**：SFT 阶段 +1.3 PDMS / +1.4 EPDMS；RL 阶段仍保持 +0.9 / +1.0，说明焦点式推理在两个训练阶段都优于纯语言推理。
- **表示与训练细节的作用**：
  - patch 引用优于文本坐标（无预热 +0.4，有预热 +0.6）；引用预热再带来 +0.3 PDMS / +0.2 EPDMS。
  - 图像条件的 patch 原型优于仅含空间索引的学习型 ID 嵌入（各 +0.3），说明 patch 引用不仅表达"看哪里"，还把该区域的**视觉语义**带入后续推理。
- **总体结论**：视觉焦点可作为场景理解与驾驶动作之间的有效

连接点，且这种连接需要**图像条件化**（而非单纯的空间索引）才能充分传递区域语义；配合 SFT → GRPO 的两阶段优化，焦点式 CoT 的收益可以在强化微调后继续保留而非被冲刷掉。

## 7. 局限性与潜在问题

- **标注覆盖与成本**：焦点标注仅覆盖 Navtrain 的 13.1% 场景，Navtest 完全无标注，因此规划侧的焦点收益是在"部分监督 + 泛化到无标注场景"的设定下取得的。这一方面说明方法不依赖测试时焦点输入（推理时由模型自行生成引用），另一方面也意味着**焦点监督的规模上限未被充分探索**——若标注比例提升，性能曲线是否继续上升仍是开放问题。
- **标注一致性未量化**：流程中 VLM 只提候选、人工做最终决策，但论文未报告多人标注的一致性指标（如 IoU / Cohen's κ），也未说明标注者数量与复核机制。焦点位置的"正确答案"在驾驶场景中本身具有多解性（驾驶员可能同时关注多个目标），单点标注可能引入噪声。
- **注视预测的监督与规划解耦**：注视损失在注视模型上训练，规划模型则通过引用 token 隐式携带空间信息，论文未明确说明规划训练是否也使用注视热力图监督，以及注视分支与规划分支是否共享同一套引用投影器参数。
- **RL 阶段的消融缺失**：表 5 的焦点表示对比只在 SFT 阶段完成，GRPO 阶段是否仍保持"patch 引用 > 文本坐标"的排序未被验证；RL 使用 PDMS 作为奖励，而 PDMS 本身与焦点定位无直接关联，存在奖励与中间表示目标错位的可能。
- **仿真评测的固有边界**：NAVSIM 为非反应式仿真，其他交通参与者不响应自车行为，难以评估交互式博弈场景（如加塞、让行协商）中的焦点推理价值；W3DA 的注视数据来自不同采集平台与车型，跨数据集评测虽已遵循 G-W3DA 准备方式，但相机内外参、驾驶员个体差异仍构成混淆因素。
- **算力与可复现性**：未给出 GPU 型号、总训练时长与随机种子方差；16 卡 × 96 GB 的规划训练门槛较高，且 GRPO 需 4000 步 × 16 rollout，复现成本大。论文也未报告多次运行的性能波动区间，因此 +0.3 ~ +1.4 量级的提升是否超出运行方差尚不明确。
- **安全性表述的克制性**：虽然 NC 与 TTC 指标突出，但论文未做长尾危险场景的专项压力测试（如遮挡行人突然横穿），因此"视觉焦点提升安全性"这一主张目前仍主要由平均指标与定性示例支撑。

## 8. 对研究与实践的启示

- **中间表示的具体化（grounding）比"更长的 CoT"更重要**：论文的核心贡献不是让推理更长或更详细，而是把推理中"看哪里"这一环从自然语言描述改写为**可直接解码回图像坐标**的引用 token。这提示 VLA 研究可以沿着"减少中间表示的语义鸿沟"这一方向推进，而非单纯扩大推理链长度。
- **视觉引用可同时承担三种角色**：输出候选（生成时可选）、输入嵌入（图像条件化）、空间读出（隐状态 × 原型矩阵 → 热力图）。这种"一物三用"的设计使注视预测不需要额外的注意力解释模块，也不需要测试时的真值提示，是一种值得借鉴的轻量级架构范式。
- **两阶段热身 + RL 的工程价值**：先用不含动作目标的 VRT 预热让模型学会"引用图像区域"，再做规划 SFT，最后 GRPO 优化闭环指标。这一课程式安排表明，把"感知对齐"与"决策优化"解耦训练，可以避免 RL 阶段因奖励稀疏而破坏中间表示的语义。
- **语言化注意力的既有脉络被推进了一步**：从 LLada、FSDAM、DualGaze-VLM 的"注意力 → 语言"到本文的"注意力 → 可寻址 token → 规划"，体现了该方向正从"解释性"走向"功能性"——注意力不再只是输出，而是推理链中的可操作变量。
- **对自动驾驶数据标注的启示**：物理风险筛选（TTC / 安全场）+ VLM 候选 + 人工定稿的三级漏斗，是一种在成本与质量之间取得平衡的可复制流程；论文给出的焦点类别分布（车辆占 84.43%）也提示，当前标注体系对弱势道路使用者（行人 2.92%、自行车 0.10%）的覆盖明显偏少，这既是数据偏差，也可能是模型在 VRU 场景下改进空间有限的原因之一。

## 9. 总体评价

**定位**：论文处于"语言化注意力 / 驾驶 VLM 推理"与"端到端规划"的交叉点，主张用一个显式、可寻址的视觉焦点 token 替换传统文本 CoT 中的空间描述，并把它嵌进"焦点 → 计划 → 轨迹"的生成序列中。

**优点**：
1. **动机清晰、痛点真实**：文本 CoT 的空间错位与"识别冲突却不减速"的失败模式，是当前驾驶 VLM 公认的短板，论文用 Figure 1 做了直观佐证。
2. **方法闭环完整**：从引用表示（PaDT 式动态引用 + 低秩投影）→ 注视读出（Gaze Adapter）→ 规划训练（三阶段）→ 数据标注（三级漏斗），各环节互相咬合，没有明显的"只做了一半"的断裂。
3. **评测维度较广**：同时在注视预测（跨三个数据集、三类难度）与端到端规划（PDMS / EPDMS 双指标）上验证，并配有自建文本 CoT 基线，避免了"只跟别人比、不跟自己比"的常见问题。
4. **消融有指向性**：表 5 把"引用形式 × 是否预热 × 引用输入是否图像条件化"逐项拆开，能回答"提升究竟来自空间索引还是视觉语义"这一关键问题。

**不足**：
1. 焦点监督覆盖面有限（13.1%），且缺乏标注一致性分析与 RL 阶段的表示消融。
2. 绝对性能虽领先，但相对文本 CoT 的增益在 0.9 ~ 1.4 PDMS 量级，属于"稳健但非颠覆"；在非反应式仿真下，这些增益能否转化为真实道路安全收益仍待验证。
3. 工程复现门槛较高，且关键超参（如注视损失权重 λ_g=3、KL 系数 0.5）缺少敏感性分析。
4. 对弱势道路使用者的焦点标注占比极低，与"安全关键场景"的宣称之间存在张力。

**一句话结论**：FocusDrive 把"看哪里"从语言描述升级为图像条件化的可寻址 token，并以完整的训练与标注流水线证明其同时改善注视预测与端到端规划；它更像是为驾驶 VLA 提供了一条**结构化的中间表示范式**，而非一次性能上的跃迁，其最大价值在于示范了如何让多模态推理的中间环节"落回像素"。
