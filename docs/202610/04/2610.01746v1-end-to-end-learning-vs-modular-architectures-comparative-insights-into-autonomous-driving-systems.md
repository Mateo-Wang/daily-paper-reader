## 摘要
自动驾驶系统已成为智能交通研究的核心焦点，端到端学习与模块化架构为其实现提供了两种突出的设计范式。端到端学习使用深度学习算法将原始感知输入直接映射到驾驶执行机构，提供了一种精简且适应性强的解决方案；而模块化架构采用基于流水线的方法，将系统划分为感知、认知、规划和控制等不同子系统。本文对这些范式进行了全面的比较分析，聚焦其优势、局限与权衡，以揭示它们对不同自动驾驶应用场景的适用性。该研究评估了可解释性、可扩展性、鲁棒性和实际应用性等关键因素。尽管端到端学习在动态环境中强调简单性和适应性，但它缺乏透明度，并且高度依赖大规模数据集。相反，模块化架构具有更优的可解释性和任务特定优化能力，但面临集成复杂性和可扩展性方面的挑战。为应对这些局限，融合两种范式优势的混合方法已经出现，为克服这些挑战提供了有前景的方向。除上述比较综合外，后续工作提出了一个四维架构选择框架，包含横跨安全性、运行环境、数据/计算资源和部署情境的十二项二值准则，并针对十个已发表的自动驾驶系统进行验证，正确推荐了 7/10 的已部署架构。本工作综合现有文献，突出两种范式之间的关键权衡，并将混合架构确定为未来研究的一个有前景的方向。

## Abstract
Autonomous driving systems have become a central focus of intelligent transportation research, with End-to-End Learning and Modular Architectures offering two prominent design paradigms for their implementation. E2E Learning uses deep learning algorithms to map raw sensory inputs directly to driving actuators, providing a streamlined and adaptable solution. while Modular Architectures employ a pipeline-based approach, dividing the system into distinct subsystems for perception, cognition, planning, and control. This paper presents a comprehensive comparative analysis of these paradigms, focusing on their strengths, limitations, and trade-offs to provide insights into their suitability for various autonomous driving applications. The study evaluates key factors such as interpretability, scalability, robustness, and real-world applicability. While End-to-End Learning emphasizes simplicity and adaptability in dynamic environments, it lacks transparency and is highly dependent on large datasets. Conversely, Modular Architectures offer superior interpretability and task-specific optimization, but face challenges related to integration complexity and scalability. To address these limitations, hybrid approaches that combine the strengths of both paradigms have emerged, offering a promising direction for overcoming these challenges. Beyond this comparative synthesis, following work proposes a Four-Dimensional Architecture Selection Framework, comprising twelve binary criteria across safety, operating environment, data/computational resources, and deployment context, and validate it against ten published autonomous driving systems, correctly recommending 7/10 deployed architectures. This work synthesizes existing literature to highlight key trade-offs between the paradigms and identifies hybrid architectures as a promising direction for future research.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：自动驾驶（AD）系统架构长期存在两大范式对立——
  - **模块化架构（Modular）**：将驾驶任务分解为传感、感知、预测/决策、规划、控制等独立子系统，通过规则化接口串联，工业界广泛采用（如 ROS 框架）。
  - **端到端学习（E2E）**：用深度网络把原始传感器输入直接映射为转向、油门、刹车等控制指令，结构简洁、更接近人类"感知—行动"一体化的驾驶方式。
- **核心问题**：两种范式在**可解释性、可扩展性、鲁棒性、实际落地性**上各有优劣，但**缺乏跨维度的系统性比较研究**，导致工程实践者难以针对具体应用场景判断应选哪种架构。
- **具体痛点**：
  - 模块化：集成复杂、误差逐级传播（如红绿灯误检可级联为碰撞）、手工特征导致泛化受限、依赖人工标注瓶颈。
  - 端到端：黑箱不可解释、难以定位错误来源、高度依赖大规模多样化数据、在罕见/长尾场景失效、缺乏中间安全检查。
- **整体含义**：论文主张架构选择不应基于"算法优越性"偏好，而应由**应用情境约束**驱动；混合架构（Hybrid）是弥合两者优势的可行方向。为此作者提出**四维架构选择框架**，作为可复用的工程决策支持工具。

## 2. 方法论：核心思想、技术细节与流程

### 2.1 范式技术梳理（综述部分）

- **模块化五模块**：传感（相机/LiDAR/雷达/GPS/IMU 多传感器融合）→ 感知（目标检测：两阶段 Faster/Mask R-CNN、单阶段 YOLO/SSD；目标跟踪：SORT、深度学习跟踪器；车道线检测）→ 预测（运动轨迹预测，线性回归为基线，深度学习为主流）→ 规划（路径规划 / 行为规划 MDP、POMDP / 运动规划图搜索与增量搜索）→ 控制（执行机构、纵向速度调节、稳定性与舒适性）。
- **端到端两条技术路线**：
  - **模仿学习（IL）**：目标为学习策略 π* 以逼近专家策略 π_E，即 π* = argmin_π D(π_E, π)；含**行为克隆**（监督学习，最小化 L2 损失 min_θ E‖π_θ − π_E‖²，存在协变量偏移与误差累积问题）与**逆强化学习 IRL**（从专家轨迹反推奖励函数，用 max_θ E_πE[G_t|r_θ] − E[G_t|r_θ] 形式建模，受专家数据噪声、高维状态空间、跨域泛化差三重挑战）。
  - **强化学习（RL）**：以 MDP（S, A, T, R）建模，最大化累积奖励；分为**基于值**（Q-learning、DQN、Double Q、优先经验回放）、**基于策略**（TRPO、PPO）、**Actor-Critic**（DPG 等，适合连续控制输出）。
  - **Teacher-Student 范式**：Teacher 用特权信息（真值他车位置、地图）训练，Student 仅用原始传感器通过行为克隆模仿 Teacher（如 "Learning by Cheating"）。
  - **辅助任务**：Uber ATG 的可解释运动规划器以 LiDAR + 地图为输入，输出边界框 + 代价体（cost volume），总损失 L = L_perception + β·L_planning，感知损失含分类/回归/IoU，规划损失用 max-margin 区分好坏轨迹；另有方法加入分割掩码、单目深度、光流作为辅助监督。
- **混合架构**：模块化感知 + 端到端路径规划（BEVFusion + CNN planner 生成密集路点），兼顾可解释性与数据驱动适应性。

### 2.2 四维架构选择框架（核心贡献）

- **四个顺序维度**：
  1. **安全与法规合规**（最硬约束，优先评估）
  2. **运行环境**（结构化程度、长尾频率、交通密度）
  3. **数据与计算资源**（标注数据集、高保真仿真器、车载推理算力）
  4. **部署与运营情境**（生产认证 vs 研究原型、组件独立更新需求、团队跨领域能力）
- **十二条二值准则（C1–C12）**，每条回答"是/否"，并指向一个或多个范式：
  - C1 法规要求全决策可追溯（ISO 26262 / UNECE WP.29）→ Modular, Hybrid
  - C2 需将故障隔离至特定组件 → Modular
  - C3 强制形式化安全认证（ASIL-C/D）→ Modular, Hybrid
  - C4 运行域高度结构化 → Modular
  - C5 长尾/罕见场景频繁 → E2E, Hybrid
  - C6 交通与行人稠密且不可预测 → E2E, Hybrid
  - C7 存在大规模标注数据集 → E2E-IL
  - C8 具备高保真仿真器 → E2E-RL
  - C9 车载推理算力严格受限 → Modular
  - C10 认证生产部署（非研究原型）→ Modular, Hybrid
  - C11 组件需独立迭代更新 → Modular
  - C12 团队兼具经典控制与深度学习跨领域能力 → Hybrid
- **决策流程**：逐条打勾 → 累加各范式信号票数 → **得票最高者即为推荐架构**（Modular / E2E-IL / E2E-RL / Hybrid）。
- **平局打破规则**：先优先被 Dimension 1（安全）信号指向的范式，其次优先匹配系统评估情境（仿真 vs 实车）的范式。论文指出当前十个验证系统均未触发平局。
- **评分约定**：C5、C6 在范式家族层面指向 E2E，因此在 Table 4 中只计入 Hybrid；IL 与 RL 的区分交由 C7、C8 处理。

## 6. 主要结论与发现

- **无单一架构在所有准则上占优**：架构选择历来由应用情境驱动，而非算法优劣。
- **模块化**：在安全关键、结构化环境、算力受限、需独立更新组件、需通过 ASIL/ISO 26262 认证的场景中最优；代价是集成复杂、误差传播、泛化受限。
- **E2E-IL**：适合数据丰富、环境非结构化、长尾频繁的场景；但可解释性低、数据需求大、过拟合风险高、缺乏中间安全检查。
- **E2E-RL**：适合仿真条件充分的研究环境（可无人类驾驶数据、在线探索训练），但训练数据效率低、计算密集、真实世界安全学习困难。
- **混合架构**：在同时需要中等可解释性与适应性的场景下最优；Uber ATG NMP 与 CaRINA Agent（2023 CARLA Challenge 双赛道表现优异）是成功案例。
- **框架有效性**：四维十二准则框架对 10 个系统给出 7/10 的正确或部分正确推荐，验证了"安全约束优先、资源与部署情境决定范式"的逻辑；但作者明确界定其适用范围为**部署阶段架构决策**，不适用于回溯分类早期研究原型。
- **未来三个开放问题**：建立标准化的跨 benchmark 跨范式评估协议；为混合架构开发可形式化验证的安全属性；通过域随机化与自适应迁移缩小端到端策略的 sim-to-real 差距。

- **填补比较框架空白**：首次将"架构选择"从经验判断转化为**结构化、可重复、可逐条核查的二值准则流程**，工程可操作性强。
- **准则设计有层次**：将安全/法规作为最硬约束置于第一维度优先评估，符合自动驾驶实际认证逻辑（ISO 26262、UNECE WP.29、ASIL-C/D）。
- **跨三十年、跨范式的验证设计**：从 ALVINN（1989）到 CaRINA Agent（2023），覆盖模块化、E2E-IL、E2E-RL、混合四类，样本时间跨度大、类型分布均衡。
- **学术诚实度高**：明确承认 Roach 是真实不匹配、明确指出 ALVINN/PilotNet 属于框架范围之外，而非强行解释为成功；主动声明未采用 PRISMA 系统综述协议。
- **技术综述较扎实**：对 IL（BC/IRL）、RL（值/策略/A

ctor-Critic）、Teacher-Student 范式、辅助任务监督、混合架构的梳理脉络清晰，公式（BC 的 L2 目标、IRL 的奖励反推形式、NMP 的 L = L_perception + β·L_planning）与代表性系统一一对应，便于读者快速建立技术地图。
- **混合架构被作为一等公民**：不是把 Hybrid 当作"折中妥协"，而是明确其适用区间（中等可解释性 + 中等适应性需求），并给出 Uber ATG NMP、CaRINA Agent 两个当代实证锚点，对工程决策有直接参考价值。
- **决策流程闭环**：不仅给准则，还给出"逐条打勾 → 计票 → 取最高票 → 平局打破"的完整操作链条，并说明平局规则（先安全维度、后评估情境匹配），使框架具备可执行性而非停留在概念层。
- **对指标可比性的自我约束**：作者主动在 Table 1 注明 DS、L2、碰撞率等指标评估协议不同、不可跨行直接比较，避免了综述类论文常见的"指标堆砌式误导"。

## 8. 不足与局限（批判性评价）

- **框架验证存在循环论证风险**：C1–C12 由作者依据对 10 个目标系统的既有认知反向拟定，再用同一批系统检验，本质上接近"训练集即测试集"。缺乏独立样本、留出集或第三方专家盲评，7/10 的命中率说服力有限。
- **二值准则过度简化现实决策**：真实工程中"是否需要故障隔离""算力是否受限"多为连续谱而非是/否，且不同准则权重差异巨大（如安全 vs 团队能力）。框架未引入权重、置信度或阈值，也未讨论准则冲突时的量化权衡。
- **"部分匹配"判定标准宽松**：将 TransFuser、UniAD、LAV 判为"框架预测 Hybrid、实际 E2E-IL 但含模块化辅助监督"从而计入成功，属于事后放宽标签边界。若以严格的架构标签一致性计，精确匹配仅 4/10，框架的实证支持度应更保守表述。
- **不匹配案例的解释偏向自我有利**：ALVINN、PilotNet 被归为"框架范围之外（早期研究原型）"，而 Roach 被承认为真实失败。这种"范围边界"划定虽有一定合理性，但边界由作者单方界定，缺乏可证伪的操作化定义（例如"何谓部署阶段"）。
- **无跨范式定量性能比较**：论文未回答"在同等条件下混合架构是否真的优于纯 E2E 或纯模块化"这一关键实证问题，仅停留在逻辑推荐层面。缺少受控对比实验（如同一 CARLA 场景下四类架构的同口径评测）。
- **文献方法非系统化**：明确声明未采用 PRISMA，检索依赖引用量与 venue 偏好，可能遗漏工业界未发表方案、负面结果与小语种文献，存在发表偏倚（publication bias）与"成功案例偏差"。
- **技术深度不均衡**：对模块化五模块的描述偏教科书式（YOLO/SSD、SORT、MDP/POMDP 等均为概述），对 2023 年后的新进展（如端到端大模型、VLA、世界模型、扩散策略）覆盖不足，时间线虽标至 2025 但实质内容止于 2023 年系统。
- **缺少成本与组织维度**：准则 C12 涉及团队能力，但未纳入开发成本、维护成本、数据采集成本、法规认证周期等经济因素，而这些在真实架构决策中往往具有决定性。
- **未给出混合架构的设计方法论**：论文主张 Hybrid 是方向，但未说明"在何处切分模块化与端到端"（感知端？规划端？控制端？）、如何保证接口可验证性，缺少可落地的架构模式（pattern）指导。

## 9. 启示与展望

- **对工程实践者**：该框架可作为架构评审的**检查清单（checklist）**使用——先锁定安全/法规硬约束，再依次评估运行环境、数据算力、部署运营，能在早期避免"为技术而技术"的架构选型偏差。
- **对研究者**：论文揭示的核心空白是**跨范式统一评测基准**。若能在同一仿真器、同一场景集、同一指标口径下横向对比 Modular / E2E-IL / E2E-RL / Hybrid，将显著提升该领域结论的可比性。
- **对混合架构**：最有价值的研究方向不是"哪种范式更好"，而是**"在哪里混合"**——例如模块化感知 + 端到端规划、端到端感知 + 形式化验证的安全监控器（runtime monitor / safety shield），以及混合架构的安全属性形式化证明。
- **对 sim-to-real**：作者提出的域随机化与自适应迁移，与当前世界模型、神经仿真、闭环数据引擎趋势一致，是缩小 E2E 落地鸿沟的关键路径。
- **总体评价**：本文的贡献主要在于**决策框架与叙事综合**，而非新算法或新实验。其价值取决于框架能否被后续工作独立检验、修订与量化加权；在此之前，宜将其视为一份结构清晰、态度诚实的**工程决策辅助工具**，而非具有实证定论的比较研究。
