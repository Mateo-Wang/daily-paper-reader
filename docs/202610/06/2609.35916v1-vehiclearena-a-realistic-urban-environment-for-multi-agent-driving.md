## 摘要
现实世界中的具身智能体往往在共享物理环境中追求各自独立的目标，其行动可能改变其他智能体所面临的条件。然而，现有基准通常假设共享目标或明确规定的交互协议，使得这种涌现出的物理耦合尚未得到充分探索。我们提出 VehicleArena，一个用于研究动态共享世界中独立运行智能体的 3D 城市驾驶基准。在 VehicleArena 中，由 LLM 控制的智能体必须在复杂交通中导航的同时满足不断变化的乘客请求，并且每个智能体的驾驶决策都可能重塑周围智能体的交通流、延误、风险以及后续观测。该基准提供 112 个评估任务，涵盖单智能体和多智能体驾驶。在评估的九个模型中，最高到达率在单智能体任务上仅达到 65.0%，在多智能体任务上仅达到 65.6%，而较高的乘客请求或座舱评分并不能可靠地转化为成功完成行程。此外，在匹配的多智能体运行中，相对于模拟器原生的交通控制器，每个被测焦点策略都会降低周围车辆的到达率，揭示出焦点车辆本身之外可度量的外部性。

## Abstract
Real-world embodied agents often pursue independent objectives within a shared physical environment, where their actions can alter the conditions faced by others. Existing benchmarks, however, typically assume shared goals or explicitly prescribed interaction protocols, leaving such emergent physical coupling underexplored. We introduce VehicleArena, a 3D urban-driving benchmark for studying independently operating agents in a dynamic shared world. In VehicleArena, LLM-controlled agents must fulfill evolving passenger requests while navigating complex traffic, and each agent's driving decisions can reshape traffic flow, delays, risks, and subsequent observations for surrounding agents. The benchmark provides 112 evaluation tasks spanning single-agent and multi-agent driving. Across nine evaluated models, the highest arrival rates reach only 65.0% on single-agent tasks and 65.6% on multi-agent tasks, while strong passenger-request or cabin scores do not reliably translate into successful trip completion. Moreover, in matched multi-agent runs, every tested focal policy reduces the arrival rate of surrounding vehicles relative to the simulator's native traffic controller, revealing measurable externalities beyond the focal vehicle itself.

# VehicleArena 论文总结

## 1. 核心问题与研究动机

- **背景割裂**：现有具身驾驶研究沿两条独立路线推进——闭环驾驶基准（CARLA、SMARTS、MetaDrive、SUMO、LMDrive、DriveArena、LimSim++ 等）聚焦自车感知/规划/指令跟随；智能座舱环境（如 VehicleWorld）聚焦车内交互与设备控制。二者通常被孤立评估，导致"乘客意图与座舱交互"和"物理驾驶过程"被割裂，难以研究智能体如何在持续变化的道路环境中响应不断演化的乘客请求。
- **多智能体假设过强**：现有多智能体 LLM 基准（CAMEL、ChatDev、MetaGPT、PARTNR、SOTOPIA、MultiAgentBench、BattleAgentBench）大多通过共享目标、角色扮演、协作/竞争或预设交互协议来定义智能体关系。
- **核心问题**：论文提出 **"独立目标的物理共存"（independent-objective physical coexistence）** 设定——智能体各自服务不同乘客、追求独立目标，彼此不共享计划或通信协议，仅通过共享物理环境中的行为后果相互耦合（变道、让行、急停、犹豫会立即改变邻近智能体的观测、风险与可行动作）。
- **关键追问**：当 LLM 智能体必须同时应对变化的用户需求和其他独立行动智能体的不可预测后果时，是否仍能保持可靠与安全？

## 2. 方法论

### 2.1 整体架构
- **统一闭环世界**：SUMO 推进车辆运动与交通交互，同步 Web3D 渲染把世界状态暴露给智能体；交通流、座舱状态、环境事件沿同一仿真时间线演化。
- **三类智能体角色**（共享同一世界状态与仿真时钟，但职责与信息访问不同）：
  - **Personal Agent (PA)**：以乘客身份表达需求，不能直接操纵车辆。
  - **Driving Agent (DA)**：决定如何驾驶并服务乘客请求。
  - **Judge**：独立评估执行是否满足请求，只观察与评估、不控制车辆。
- 车辆可由 LLM 驱动或由 SUMO 原生逻辑控制，因此可把背景车"升级"为独立智能体而不改变环境。

### 2.2 Driving-Agent Harness（驾驶智能体执行框架）
- **观察–行动会话循环**：每次 wake 时，harness 将当前观测、乘客更新与保留的任务上下文合并；DA 可多轮调用工具查看与操作后再结束会话。近期交互历史与持久 Todo board 跨 wake 保存未完成工作。
- **非每步调用**：DA 不由物理步驱动，而由启动/相关事件触发 wake，并自主控制周期性 heartbeat（可设 0.1–30 仿真秒）及 `schedule_next_wake`——"何时推理"本身属于策略的一部分。多个 DA 在同一仿真时刻唤醒时观察同一已提交路况并行执行，缓冲的运动指令在下一次物理步前统一提交。
- **渐进式工具发现与技能**：核心驾驶工具立即可用，其他能力需通过检查已安装模块并加载接口来发现；可选 skill 提供多步操作的程序性指导但不规定驾驶策略。
- **驾驶动作空间**：持久化目标速度指令、常规/紧急制动、相邻车道变道、路口机动（转向/直行）；路径规划只提供导航指引而非自动跟随，DA 需自行选择机动与打灯。指令表示"意图控制"而非瞬时状态改变——制动需要时间，变道可能受周边车辆约束。座舱工具同样修改持久设备状态而非仅输出文本。

### 2.3 PA 与 Judge Harness
- **PA 唤醒源**：乘客可见的共享事件（仿真开始、声学提示、天气变化、昼夜变化）、硬刹车边沿（加速度 ≤ −3 m/s² 持续 0.3 s，需重新武装）、长时间停车边沿（<0.5 km/h 持续 15 s）、独立随机唤醒（U(15,45) 仿真秒）；五秒冷却合并同类事件。Judge 检查、工具回执、请求过期、DA heartbeat 不触发 PA 唤醒。
- **声明式延迟触发器目录**：时间（有界延迟）、路径与地图（接近/进入/离开下一路口、距目的地低于阈值）、车辆状态（停车、恢复行驶、速度阈值保持一段时间）、环境（天气或入夜转变）；只向 PA 展示当前可行且参数有界的谓词，谓词按 0.1 秒物理分辨率检查。
- **请求生命周期**：请求冻结后核心/次要判据固定；Judge 在立即创建或触发激活后 0.1 / 1 / 3 秒三个偏移处检查，每阶段最多三次；中间检查保留判据状态，最终裁定给出单一等级。状态包括 Created/waiting、Activated/checking、Completed、Uncompleted/unverified、Superseded/episode ended、NA/infrastructure failure，终端状态作为 coverage 单独报告而不静默并入请求分数。
- **算法流程（Algorithm 1）**：在每个世界边界，若 PA 到期则计算可用触发器、生成结构化请求更新、校验并冻结验收判据、应用更新（仅乘客更新返回给 DA）；随后对每个待决请求更新验证调度，若检查到期则收集执行证据、验证请求、记录有效裁定或显式未评分状态，完成或到最后检查点则关闭；验证不产生驾驶唤醒。
- **任务截止时间**：以 SUMO 控制自车的参考运行标定，\(T_{\text{limit}} = \max(T_{\text{cal}}, T_{\text{event}}) + \Delta\)，其中 \(T_{\text{cal}}\) 为必需 SUMO 车辆的最后到达时间（排除持久障碍、不等待 LLM 同伴），\(T_{\text{event}}\) 为最后计划环境事件，裕度 \(\Delta\) 通常为 10 秒，全程固定。

### 2.4 评估指标（六类，互不合并为单一分数）
- **行程完成 A**：在 \(T_{\text{limit}}\) 前到达且无碰撞/路线失败的任务百分比。
- **驾驶质量 D**：从 100 起按违规扣分；有责碰撞或闯红灯直接归零。
- **乘客请求满足 R**：Judge 的 A–F 等级映射为 100/80/60/40/20/0。
- **座舱合规 C**：跨检查点的字段加权准确率。
- **外部性 E**：相对 SUMO 的 NPC 碰撞/未到达变化及排队时间、行程时间正增量（车辆秒）。
- **效率 K**：每任务输入/输出 token 数。
- 补充：完成度加权指数 \(I = A \cdot \frac{D+R+C}{3}\)（A 以百分比表示），仅用于规划效率的对比可视化，非额外评估指标。

- **分析维度**：主表四指标（Arr./Drive/Req./Cabin）分组对比；规划效率分析（每任务 wake 数、每次 wake 工具调用数，Basic 与 Multi-Agent 分开）；速度与碰撞汇总（112 任务池化）；技能加载与工具调用族分布（Figure 4 + 表 11）；token 成本 vs 完成度加权指数（Figure 6）；周边交通负担雷达（到达延误、排队延误、碰撞超出、未到达，相对匹配 SUMO 运行）。
- **消融实验**：关闭自车 PA 与 Passenger Judge（保留固定同伴的二者），仅覆盖 **Kimi-K3 与 GLM-5.3-Flash 两个模型**（表 3）。
- **充分性与公平性评估**：
  - 优点：同一批任务 ID 与评分规则、匹配的 SUMO oracle 与逐车辆 ID 配对、同伴模型/提示/PA 分配在对比中固定、每个任务三次重复、指标分母与未评分状态显式报告，整体较客观。
  - 局限：消融仅两个模型；重复次数仅 3；MultiLLM 的同伴模型固定为单一 Qwen3.8-27B，跨模型多智能体交互的泛化性未检验；Figure 5 雷达仅展示 7 个模型；未报告统计显著性检验或方差区间；交通影响雷达把碰撞率下降截断为零，视觉摘要为等权平均，作者自述"仅为视觉摘要，非额外评估指标"。

## 6. 主要结论与发现

- **到达率整体偏低**：单智能体最高仅 65.0%（Qwen3.8-Max），多智能体最高 65.6%（Qwen3.8-Max）；DeepSeek-V4.1-Flash 为 62.5% / 56.3%。
- **高分不等于完成行程**：GPT-5.6-Sol 取得最高 Cabin（90.2 Basic / 94.0 Multi-Agent）与最高 Drive（87.2 Multi-Agent），但到达率仅 20.0% / 9.4%，平均速度最低（11.4 km/h）且无碰撞——与"截止时间前推进不足"一致。指标排序在不同维度间并不一致。
