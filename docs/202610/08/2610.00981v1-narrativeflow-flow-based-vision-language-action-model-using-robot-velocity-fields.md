## 摘要
我们关注语言条件的基于流的操作，其中机器人流（机器人速度场）作为与具身无关的、以运动为中心的表征，用于利用从多个机器人平台收集的数据。该任务至关重要，因为语言条件操作对实际机器人系统必不可少，但扩展机器人基础模型仍受限于劳动密集的具身特定数据收集。现有方法要么用稀疏关键点位移粗略近似机器人流，要么无法处理语言条件操作。为解决这一局限，我们提出 NarrativeFlow，它使用以语言为条件的流匹配公式，将机器人流建模为连续速度场。因此，NarrativeFlow 生成与真实世界操作物理一致的机器人流。为验证 NarrativeFlow，我们在语言条件操作的标准数据集上进行了实验。实验结果表明，NarrativeFlow 在标准评估指标上优于代表性基线方法。此外，通过真实世界实验，我们表明 NarrativeFlow 在多种操作任务上比基线方法取得更高的成功率。项目页面见 https://shota0520.github.io/NarrativeFlow-project-page/

## Abstract
We focus on language-conditioned flow-based manipulation, where robot flows (robot velocity fields) serve as embodiment-agnostic, motion-centric representations for leveraging data collected from multiple robot platforms. This task is crucial because language-conditioned manipulation is essential for practical robotic systems, yet scaling robot foundation models remains limited by the labor-intensive collection of embodiment-specific data. Existing methods either coarsely approximate robot flows with sparse keypoint displacements, or cannot handle language-conditioned manipulation. To address this limitation, we propose NarrativeFlow, which models robot flows as continuous velocity fields using a flow-matching formulation conditioned on language. Accordingly, NarrativeFlow generates robot flows that are physically consistent with real-world manipulation. To validate NarrativeFlow, we have conducted experiments on standard datasets for language-conditioned manipulation. The experimental results show that NarrativeFlow outperforms representative baseline methods on standard evaluation metrics. Furthermore, through real-world experiments, we show that NarrativeFlow achieves higher success rates than baseline methods across multiple manipulation tasks. The project page is available at https://shota0520.github.io/NarrativeFlow-project-page/

## 1. 论文的核心问题与整体含义

- **研究背景**：制造业、物流、医疗等领域劳动力短缺，推动了对能理解自然语言指令、跨多样环境执行任务的机器人系统的需求。机器人基础模型通常依赖多平台大规模数据预训练，数据规模与多样性是性能关键。
- **核心痛点**：
  - 扩展机器人基础模型仍受限于**劳动密集的具身特定数据采集**，跨平台数据难以复用。
  - 机器人流（robot flow）作为**具身无关的运动中心表征**，可从任意机器人视频中提取，理论上可缓解该问题，但现有方法存在两类缺陷：
    1. **稀疏关键点位移近似**：多数流式操作方法（如 Track2Act、Im2Flow2Act、FLIP）预测稀疏关键点坐标再推导流，仅粗略近似连续运动，并隐含"位移确定性"这一在实践中很少成立的假设。
    2. **无法处理语言条件**：Flow as Flow 能建模稠密速度场，但仅支持目标图像条件（goal-conditioned），无法在推理时无目标图像的场景下使用语言指令。
  - 此外，现有方法训练时仅使用主流量生成损失，**缺乏对任务相关语义的显式监督**，易被背景外观、光照等任务无关视觉细节误导。
- **整体含义**：作者提出 NarrativeFlow，将机器人流建模为**语言条件下的连续概率速度场**，并引入辅助损失对齐任务相关场景变化，从而在跨具身数据上实现高质量、物理一致的机器人流生成，支撑下游操作任务。

## 2. 论文提出的方法论

### 2.1 核心思想
- 将机器人流表述为**概率速度场**，在**流匹配（flow matching）框架**下以语言为条件生成。
- 引入 **Narrative Delta 损失**作为辅助目标，将模型中间表征对齐到任务相关场景变化的"叙事表征"。
- 引入**两个子任务 token**，分别用于条件化 Flow-as-Flow 模块和计算 Narrative Delta 损失，缓解两条下游路径学习信号的相互干扰。

### 2.2 关键技术细节

- **输入与编码**：
  - 输入为指令 ℓ 与初始图像 $I_0$。
  - 语言用 Qwen3-Embedding-0.6B 编码为 $z_{lang}$，图像用 DINOv3-ViT-B/16 编码为 $z_{img}$。

- **视觉-语言融合编码器**：
  - 将两个子任务 token 与 $z_{img}$、$z_{lang}$ 拼接，输入 4 层 Transformer 编码器。
  - 两个子任务 token 的输出分别投影为 $z^{(1)}_{st}$（用于条件化 Flow-as-Flow）和 $z^{(2)}_{st}$（用于计算 Narrative Delta 损失）。

- **Narrative Delta 损失**：
  - 训练时利用 MLLM（Qwen3.5-9B）基于 $I_0$、目标图像 $G$ 及提示词生成 $N_c=5$ 条描述任务相关场景变化的字幕。
  - 用 Qwen3-Embedding-0.6B 嵌入字幕，得到目标叙事表征 $\{z^{(i)}_{ND}\}_{i=1}^{N_c}$。
  - 损失函数为余弦相似度形式：
    $$\mathcal{L}_{ND} = \frac{1}{N_c}\sum_{i=1}^{N_c}\left[1 - \text{cossim}\left(z^{(2)}_{st}, z^{(i)}_{ND}\right)\right]$$
  - 仅在训练时使用，推理时无需 $G$。

- **Flow-as-Flow 模块**：
  - 在 $I_0$ 上均匀初始化 $N=10\times10$ 个点，通过积分速度场获得未来位置。
  - 目标速度场含稳定项：$v(\Xi_t, X, t) = \dot{\Xi}_t - k(X - \Xi_t)$，其中 $X \sim \mathcal{N}(\Xi_t, \sigma_0^2 e^{-2kt}I)$。
  - 采用 DiT 架构，每个 DiT 块通过 adaLN-Zero 调制；条件向量由 $z^{(1)}_{st}$、ResNet-18 编码的 $I_0$ 与正弦位置编码的 $t$ 相加构成。
  - 推理时：$X_t = X_0 + \int_0^t v_\theta(X_\tau, \tau \mid I_0, z^{(1)}_{st}, X_{<\tau})\,d\tau$。

- **总损失**：
  $$\mathcal{L} = \mathcal{L}_{FaF} + \lambda \mathcal{L}_{ND}$$
  其中 $\mathcal{L}_{FaF}$ 为条件流匹配损失。$\lambda$ 在训练前 30k 步设为 0.1，之后设为 $1.0\times10^{-5}$。

- **训练流程**：先用跨具身数据集训练模型；部署时给定指令与初始图像生成机器人流，再由流条件操作策略（DiT 架构）输出末端执行器位姿。

- **定量结果**：
  - Fractal：ADE 21.68、FDE 31.59、LTDR 76.29%，优于最佳基线（ADE 37.14）。
  - Bridge V2：ADE 30.59、FDE 42.42、LTDR 66.30%，优于最佳基线（ADE 50.73）。

- **真实世界结果**：平均成功率 **55%**，比最强基线 Im2Flow2Act（42%）高 **13 个百分点**；与 Oracle（63%）差距为 8 个百分点，而 Im2Flow2Act 差距为 21 个百分点。
- **消融结论**：
  - 双子任务 token 优于无 token 与单一共享 token。
  - Narrative Delta 损失显著提升性能（移除后 ADE 分别变差 4.15 / 3.20）。
  - 多个字幕（$N_c=5$）优于单个；余弦相似度优于 L2；$I_0/G$ 字幕优于视频字幕。

## 7. 优点

- **方法创新**：
  - 首次在**语言条件**下将机器人流建模为连续概率速度场，突破 Flow as Flow 仅支持目标图像条件的限制。
  - Narrative Delta 损失提供任务相关语义的显式辅助监督，提升对背景/光照等干扰的鲁棒性。
  - 双子任务 token 设计有效解耦两条下游路径的学习信号，思路简洁且消融验证有效。
  - 训练时利用目标图像但推理时无需目标图像，兼顾监督信号与部署可行性。
- **实验设计**：
  - 在两个具身不同的标准数据集上验证，体现跨具身泛化。
  - 真实世界实验覆盖 13 个移动操作任务，含精细对齐（叠杯）与多步操作，验证下游有效性。
  - 消融系统全面（token、损失、字幕数量/来源、损失函数、MLLM 规模、速度场建模）。
  - 提供失败案例分析，指出多模态语言理解是主要瓶颈，并给出可行改进方向（对象中心区域提议模块）。
- **效率**：推理仅 62 ms，模型规模 487M，训练 6 小时，资源需求相对可控。

## 8. 不足与局限

- **2D 流限制**：仅在图像平面建模机器人流，无法处理深度方向运动（如从书架上沿视线方向直接抽出书本），此类场景中 2D 流几乎为零但实际 3D 运动显著。作者将 3D 提升列为未来工作。
- **语言理解瓶颈**：误差分析显示主要失败原因为**多模态语言理解错误**（100 例中 30 例），如将"knob-like object"误判为抽屉把手。
- **依赖外部组件**：真值流依赖 CoTracker3，末端执行器掩码依赖微调 Robot-SAM，字幕生成依赖 Qwen3.5-9B，可能引入误差传播与额外成本。
- **数据标注噪声**：Bridge V2 中 17 例标注错误（13 例为人类语言标注错误），影响训练与评估可靠性。
- **实验覆盖局限**：
  - 测试集各仅 2,000 样本，真实世界每任务仅 20 次试验，统计功效有限。
  - 仅使用 Fractal 与 Bridge V2 两个数据集，未覆盖 DROID、AgiBot World 等更大多样化平台。
  - 真实世界任务限于桌面/移动操作，未涉及可变形物体、双臂等复杂场景。
- **假设限制**：假设固定相机设置下末端执行器在初始图像中可见，实际部署中可能不成立。
- **与 Oracle 仍有差距**：平均成功率距 Oracle 差 8 个百分点，说明生成流质量仍有提升空间。
