## 摘要
在未知室内环境中进行视觉-语言导航（VLN）对真实机器人应用具有重要价值，智能体必须在没有预建地图或固定物体词汇表的条件下遵循自然语言指令、定位物体并回答空间问题。多模态视觉-语言模型（VLM）具备强大的开放词汇定位能力与零样本推理能力，但难以直接从图像中输出可靠的度量量，如距离、方位和比较性空间关系。现有方法通过将几何信息嵌入人工设计的流水线，或让模型输出航路点来应对这一问题，但这需要针对不同机器人、任务或词汇表修改控制栈。我们提出 AnchorVLN，一个开放词汇 VLN 系统，其构建遵循一条简单准则：VLM 负责提出语义，几何负责决定度量。该系统以 EMBODIED-NAV-MCP 的形式实现，这是一个模型上下文协议（MCP）服务器，由 VLM 智能体通过一组紧凑的可调用工具进行驱动。由于没有任何工具接受以米为单位的距离或以弧度为单位的方位，该模式在不修改下游自主性栈的前提下强制实现了语义与几何之间的边界。我们在 CMU 视觉-语言导航挑战赛 2026 的两项任务上进行了基准测试：涵盖 15 个场景的 30 道指令遵循问题，以及一个冻结的 45 题物体指代数据集。完整系统在指令遵循任务上达到 64.4%，在去除控制器建模后下降 13.3 个百分点（t = 2.77）。在物体指代任务上，几何锚定在 45 道题中的 10 道上达到挑战赛的重叠阈值，而直接坐标估计为 45 道题中 0 道，并将中心误差中位数从 3.37 米降至 2.48 米。

## Abstract
Vision-Language Navigation (VLN) in unseen indoor environments is useful in real-world robotics, where an agent must follow natural-language instructions, locate objects, and answer spatial questions without a pre-built map or fixed object vocabulary. Multimodal vision-language models (VLMs) provide strong open-vocabulary grounding and zero-shot reasoning, but struggle to emit reliable metric quantities such as range, bearing, and comparative spatial relations directly from images. Existing approaches address this by folding geometry into hand-engineered pipelines or asking models to output waypoints, requiring changes to the control stack for different robots, tasks, or vocabularies. We introduce AnchorVLN, an open-vocabulary VLN system built on a simple rule: the VLM proposes semantics; geometry decides metrics. It is realised as EMBODIED-NAV-MCP, a Model Context Protocol (MCP) server driven by a VLM agent through a compact set of callable tools. Since no tool accepts distance in metres or bearing in radians, the schema enforces the semantic-geometry boundary without modifying the downstream autonomy stack. We benchmark both tasks of the CMU Vision-Language Navigation Challenge 2026: 30 instruction-following questions over 15 scenes and a frozen 45-question object-reference set. The full system achieves 64.4 percent on instruction following, dropping by 13.3 percentage points without controller modeling (t = 2.77). On object reference, geometric anchoring clears the challenge overlap threshold on 10 of 45 questions, versus 0 of 45 for direct coordinate estimation, reducing median center error from 3.37 m to 2.48 m.

# AnchorVLN 论文总结

## 一、核心问题与研究动机

- **背景**：未知室内环境下的视觉-语言导航（VLN）要求智能体在无预建地图、无固定物体词表的条件下，遵循自然语言指令、定位被指代物体并回答空间问题。
- **技术趋势**：多模态视觉-语言模型（VLM）具备强大的开放词汇 grounding 与零样本推理能力，自然成为这类智能体的语义前端。
- **核心痛点——度量失效**：VLM 擅长语言-视觉的语义匹配，却无法从图像可靠地输出距离（range）、方位（bearing）和比较性空间关系等**度量量**。同一个能正确 grounding“离风扇装饰最近的那盏灯”的模型，在被要求以米为单位决策时仍会编造距离或选错比较对象。
- **现有方案的不可扩展性**：
  - 把几何折进人工设计的感知-控制流水线；
  - 或让模型直接输出航路点（waypoint）。
  - 两者都要求针对每个新机器人、新任务、新词表重写控制栈。
- **本文视角转换**：把该失败视为**接口问题**而非模型能力问题，提出唯一准则——**“VLM 提出语义，几何决定度量”**（the VLM proposes semantics; geometry decides metrics）。

## 二、方法论：AnchorVLN / EMBODIED-NAV-MCP

### 2.1 核心思想

- 将开放词汇导航栈切分为 **10 个可调用工具**，由 VLM 智能体在推理时通过 Model Context Protocol（MCP）驱动。
- **关键约束**：所有工具输入均为**短语（phrase）或句柄（handle，如 `obj_7`）**，没有任何工具接受以米为单位的距离或以弧度为单位的方位。因此模型幻觉出的坐标在结构上无法到达机器人。
- 句柄是**名称而非数值**：它指向服务器持有的记录（含方位、距离、范围、地图坐标系坐标），客户端无法把句柄“变成”位置，服务器只解析自己签发过的标识符。
- 三层权威与两条边界（Fig.1）：
  - 客户端决定 **which**（去哪）；
  - 服务器决定 **how far / 拒绝**；
  - 控制器决定 **车辆最终停在哪**。
  - 上边界只传递短语与句柄；下边界即策略不再拥有驱动权之处，服务器**建模**而非**命令**控制器。

### 2.2 工具接口（Table I）

| 类别 | 工具 | 作用 |
|---|---|---|
| 感知（机器人不动） | `ground` | 短语 → 句柄，或拒绝 |
| | `expand_vocab` | 注入类别，扩展检测词表 |
| | `verify_present` | 验证某物是否存在 |
| | `nearest` / `farthest` | 比较式查询，返回句柄 + 锚点句柄 |
| | `between` | 两个句柄 → 一个“通道”（passage） |
| 运动（车辆移动） | `drive_to` | 句柄 → arrived/moved/stalled |
| | `explore` | 无目标前沿探索 |
| | `orbit` | 绕句柄走弧线以精化几何 |
| 输出 | `publish` | 提交最终答案句柄 |

- VLM 仅在三处被调用：作为 MCP 客户端、在 `ground` 内部、在维护物体图的感知进程内部。
- `nearest/farthest/between` 等为**对已有记录的算术**，不调用 VLM，因为客户端自己做比较会“可靠地返回锚点本身”这一错误答案。

### 2.3 感知关键技术细节

- **`ground` 是承重调用**：
  1. 将机载全景图展开为若干重叠的**日晷投影面（gnomonic faces）**，以保持远处小物体的分辨率；
  2. VLM 为每个候选返回一个 2D 框；
  3. 框中心反投影得到方位；
  4. 在该方位附近**窄锥内激光雷达回波的中间值距离**作为深度（取中值以避免前景/背景表面平均出“看似合理的错误数值”）。
- **三重门控（gate）**——每项都是模型看不见的两个测量之间的校验：
  - **仰角下限**：拒绝低于扫描仪最低射线的方位（否则锥体会采样到地板）；
  - **隐含尺寸门**：拒绝在返回距离上其尺度与名词矛盾的框；
  - **空锥测试**：拒绝回波过少无法聚类的方位。
  - 被门控的抬升仍产生句柄，但标记为“未测量”，此时 `drive_to` 会沿已知方位**步进一段有界距离**，往往就足以改变造成拒绝的几何条件。
- **拒绝是特性而非缺陷**：一个自信的错误坐标会被高速驶向。

### 2.4 物体图与词表维护

- 服务器维护**持久物体图**（借鉴 SysNav）：每次激光雷达扫描与识别到的物体折叠为按身份键控的记录，同一物体从新视角再现时更新而非新建记录，遮挡面转入视野时范围收紧。
- `expand_vocab` / `verify_present` 维护感知进程搜索的词表，从而影响物体图的内容。
- 比较工具的操作数来自图而非当前图像，因此**可跨越机器人见过的所有实例**。

### 2.5 运动：预测而非命令

- `drive_to` 之下是一个**有自身目标**的控制器，假设它只把航路点当作请求而非命令，且不报告到达。
- 策略既不能命令也不能读取控制器，只能探测或预测；探测每次都要跑一趟，代价高，因此服务器选择**预测**：在同一张地图上重新实现控制器目标函数，找到“预测静止点”离句柄坐标最近的那个点，发布该点而非自己真正想要的点。
- **到达判定**：基于里程计的距离测试（因为模型最不擅长的判断就是“从只是可见的视角宣称已抵达”）。
- **`explore`**：不取句柄、不承诺目的地；短语连续多次无法解析时放弃固定目标，驶向未探索空间前沿；检测到新物体后拉回目标驱动；覆盖进入平台期则结束搜索。
- **`orbit`**：绕已抵达句柄走弧线视角，单侧测量会低估尺寸、遮挡远面、朝向靠猜，多视角折叠进同一记录以精化。

### 3.2 评测指标

- **指令遵循**：

  - Hit rate（IoU ≥ 0.1）；
  - Mean IoU；

## 六、主要结论与发现

1. **只有控制器建模对指令遵循得分有实质影响**：移除它损失 **13.3 个百分点**（t = 2.77）；移除 Lift 仅损失 0.8 点（t = 0.23），其点估计本身就与零一致。
2. **Lift 的准确度被平台吸收**：Lift 的扫描距离中位绝对误差仅 **0.16 m**，而模型自报的 `distance_m` 误差达 **2.80 m**（比永远回答 5.0 m 还差）；但航路点节点会针对自身地形图重新规划每个发布点，使 1.47 m 的瞄准中位差最终只变成车辆停止位置 **0.15 m** 的差异。因此 Lift 的真实回报是**成本而非分数**：每题少 1.45 次 grounding 调用（t = 2.86）。
3. **得分看不见的，距离看得见**：两个消融朝相反方向失败——w/o Lift 行驶 1.53× 参考长度（模型米数超调），w/o Platform Model 为 0.79×（无建模的自由空间检查只会把航路点往里拉）；两者同去则 1.00×，与正确无异，却比完整系统低 10.0 分（t = 2.38）——**“开对距离”不等于“开到对地方”**。
4. **最近接近距离更早分辨**：移除平台模型使机器人 30 题中有 24 题远了 0.52 m（t = 3.42，强于得分的 t = 2.77）；在到达容差 1.25 m 下，这已是“到达与未到达”的大部分差距。在最后两个场景解包前的 26 题上，米制指标已分离两个臂，比得分**提前四题**。
5. **物体指代：几何锚定是决定性的**：
   - 完整系统 **22%（10/45）** 命中，平均 IoU 0.060，命中时框中心平均距真值 **36 cm**（覆盖有限，但一旦提交就几何紧凑）；
   - 让模型自己输出 (x, y, z)（model-metric）则 **0/45** 命中，平均 IoU 0.000——该臂根本不报告范围（默认立方体），重叠指标无从给分；**失败是几何的，不是语义的**。
   - 同模型、同导航、同场景，仅最终框的来源不同：grounded 系统距真值 0.23 m，model-metric 臂“估计约 3.5 m

（接上文）……而真实距离约 1.2 m，误差约 2.3 m，且方向判断也不稳定。这说明**语义前端完全相同、导航轨迹完全相同的前提下，唯一改变的只是最终框的来源**，结果就从 22% 命中塌缩到 0%——这是全文最干净的对照，直接把失败归因锁定在"度量由谁产出"这一接口选择上。

6. **拒答与覆盖的代价结构**：
   - `ground` 的拒绝在指令遵循中几乎不产生负面后果，因为 `drive_to` 的"未测量"分支会沿方位步进有界距离，从而改变几何条件、使下一次调用有机会成功；
   - 但在物体指代任务中，拒绝直接等于漏检，无法通过移动弥补，这解释了为什么完整系统的命中率只有 22% 而一旦命中却极为精确（36 cm 中心误差）。**精度与召回被刻意分开**：系统选择"宁可不说，也不说错"，因为一个错的 3D 框会被下游当作可行驶目标。
   - 隐含代价是**延迟**：每次门控拒绝都对应一次前沿模型往返（约半分钟），10 分钟预算下最多约 20 次工具调用，这一硬约束反过来塑造了 `explore` 的"覆盖平台期即终止"策略。

7. **探索与词表的定性结论**：
   - 词表注入（Fig.3）显示 `expand_vocab` 能在不重启感知进程的前提下让后续帧检出先前被漏掉的类别，验证了"感知搜索空间可被策略在推理时修改"这一设计；
   - 探索鲁棒性对比（Fig.2）表明 `explore` 的无目标前沿行为在短语连续解析失败时提供了可恢复性，代价是 TL ratio 上升；
   - Type-3 指令轨迹（Fig.4）展示了典型调用序列：`ground` → 门控拒绝 → `drive_to` 步进 → `orbit` → `ground` 成功 → `drive_to` 到达 → `publish`，即**几何精化是通过移动完成的，而不是通过更长的提示词**。

## 七、讨论与局限

### 7.1 作者自陈的局限

- **样本量**：30 题 / 45 题均为开发集规模，作者自行给出最小可分辨差异（约 9.4 个百分点）并要求读者以此为准解读所有数字；
- **评测器封闭**：到达容差、实例匹配规则均为自建，作者明确承认"换一套规则数字就会变"，并以"报告较不讨喜的那一个"作为可复现性承诺；
- **无官方测试集结果**：全部结论停留在开发集，未提交隐藏测试集；
- **延迟是结构性瓶颈**：2 Hz 平台与每步约 30 秒的模型往返之间存在三个数量级的差距，系统在实时性上不具备部署条件。

### 7.2 可进一步质疑之处

- **平台模型的可迁移性**：整个方法的核心收益来自"服务器重新实现控制器目标函数"，这要求对下游控制器有足够精确的白盒或灰盒模型。若换成一个无法建模的黑盒控制器（例如端到端学习式局部策略），本文最有效的组件（w/o Platform Model 损失 13.3 点）可能无法直接移植，方法的可扩展性主张因此部分依赖于"控制器可被重实现"这一前提。
- **MCP 作为信任边界的强度**：论文用"句柄是服务器签发的名称"来论证幻觉坐标在结构上不可达，这在协议层面成立；但若 VLM 客户端被允许调用 `expand_vocab` 注入任意类别，感知进程的搜索空间实际上由模型间接控制，边界是"数值不可注入"而非"语义不可注入"。
- **单模型依赖**：全部推理由 Claude Opus 5 承担，未报告更换 VLM 后的敏感性。鉴于核心论点是"VLM 的度量不可信、语义可信"，一个自然的检验是换用更弱或更强的 VLM 观察语义侧是否仍足够——论文未做此实验。
- **消融的解析判定依赖后加入的数据**：Naive 臂只有在最后两个场景加入后才越过可分辨阈值，这提示部分结论对样本构成较敏感；作者诚实披露了这一点，但也意味着"Naive 显著更差"这一结论的稳健性未被独立验证。

### 7.3 与既有路线的对比意义

- 相对**端到端 VLN 模型**：本文不训练策略，把泛化问题转化为工具接口设计问题，因此不受训练场景分布限制，但也放弃了数据驱动带来的行为平滑性；
- 相对**模块化感知-控制流水线**：本文的模块由 VLM 在推理时按需编排（MCP），而非由工程师预先固定调用顺序，词表与目标均由模型在运行时决定；
- 相对**让 VLM 直接输出航路点**：本文的对照实验（model-metric 臂 0/45）给出了该路线在需要度量输出时的直接反例。

## 八、总体评价与启示

### 8.1 贡献提炼

1. **概念贡献**：把"VLM 不会量距离"从模型缺陷重新表述为**接口选择问题**，并提出可操作的准则——"VLM 提出语义，几何决定度量"；
2. **系统贡献**：给出 AnchorVLN / EMBODIED-NAV-MCP 的完整 10 工具接口，其中所有输入均为短语或句柄，从结构上封堵数值幻觉；
3. **工程贡献**：三重门控（仰角下限、隐含尺寸门、空锥测试）、中值距离抬升、持久物体图、控制器预测式建模等具体机制；
4. **实证贡献**：在统一平台上给出 5 臂消融，并主动量化噪声底与可分辨度，其中"w/o Platform Model 损失 13.3 点"与"model-metric 命中 0/45"是两个最有力的结论。

### 8.2 方法论的普适启示

- **把不确定性变成接口约束，而不是提示词请求**："请不要编造距离"是无效的，而"没有任何工具接受距离"是有效的。这一思路可推广到任何需要 LLM 与物理系统交互的场景（机器人操作、具身问答、工业控制）。
- **测量精度与任务得分之间可能隔着下游吸收层**：Lift 把测距误差从 2.80 m 压到 0.16 m，但最终车辆停止位置只差 0.15 m，得分几乎不变；真正被节省的是调用次数。这提示评估具身系统时应同时报告**成本指标**与**质量指标**，否则会误判组件的价值。
- **"开对距离"≠"开到对地方"**：TL ratio 接近 1.0 的臂可以比完整系统低 10 分，说明轨迹长度类指标单独使用具有误导性，必须与任务完成度联合解读。
- **更细的度量指标可能更早收敛**：最近接近距离比 Challenge Score 提前四题分离两个消融臂，对小样本具身评测而言，选择低方差指标比增加样本量更经济。

### 8.3 一句话结论

AnchorVLN 的实质主张是：在开放词汇具身导航中，**VLM 应当是语义的提议者与工具编排者，而不是几何量的生产者**；论文用一套"只收短语与句柄"的工具协议强制实施这一分工，并以消融实验证明——当模型被允许直接输出度量时，性能不是下降，而是归零。
