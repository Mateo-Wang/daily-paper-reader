## 摘要
一个智能体AI驾驶辅助框架，将感知、合规推理、车辆状态解释和安全仲裁集成到模块化且可审计的流水线中。该架构称为DriveMCP，包含类传感器感知栈以及作为视觉-语言前端的DriveLM，以生成图结构场景理解（图视觉问答）和基于语言的驾驶信息。world_state中的关键合规元素，包括标示限速和司法辖区线索，通过结构化解析层从DriveLM输出中推导，而非作为模拟器真值注入。有状态编排层协调以模型上下文协议（MCP）服务器形式暴露的专用专家：(i) 规则服务器，对特定司法辖区的交通法规和标志惯例执行检索增强的合规推理；(ii) 天气服务器，估计牵引力风险和情境化速度建议；(iii) MCP-CAN服务器，呈现控制器局域网（CAN）/车载诊断（OBD）遥测和诊断上下文，用于健康感知的风险塑造。这些输出被融合以生成结构化决策，提示推荐行动方案。结果随后由受责任敏感安全（RSS）启发的护栏进一步过滤，该护栏在有界在线自适应下仲裁“说”与“做”的决策。在多语言、跨境和动态限速场景的CARLA仿真中，相较于VLM-Direct、VLM-Direct+RAG和VLM-Tools-NoArbiter基线，DriveMCP减少了交通违规和超速，同时改善了危险响应时间并保持亚秒级建议延迟。

## Abstract
An agentic AI driver-assistance framework that integrates perception, compliance reasoning, vehicle-state interpretation, and safety arbitration into a modular and auditable pipeline. The architecture, referred to as DriveMCP, incorporates a sensor-like perception stack alongside DriveLM as the vision-language front end to generate a graph-structured scene understanding (Graph Visual Question Answering) and language-grounded driving information. Key compliance elements in world_state, including posted speed limits and jurisdiction cues, are derived from DriveLM outputs through a structured parsing layer rather than being injected as simulator ground truth. A stateful orchestration layer coordinates specialized experts exposed as Model Context Protocol (MCP) servers: (i) a Rules server that performs retrieval-augmented compliance reasoning over jurisdiction-specific traffic codes and sign conventions, (ii) a Weather server that estimates traction risk and contextual speed advisories, and (iii) an MCP-CAN server that surfaces Controller Area Network (CAN)/On-Board Diagnostics (OBD) telemetry and diagnostic context for health-aware risk shaping. These outputs are fused to generate a structured decision that prompts a recommended course of action. The outcome is then further filtered by a Responsibility-Sensitive Safety (RSS)-inspired guardrail that arbitrates speak versus act decisions under bounded online adaptation. In CARLA simulation across multilingual, cross-border, and dynamic speed-limit scenarios, DriveMCP reduces traffic infractions and overspeed relative to the VLM-Direct, VLM-Direct+RAG, and VLM-Tools-NoArbiter baselines, while improving hazard response time and maintaining sub-second advisory latency.

- **整体含义**：论文提出 **DriveMCP**——一个模块化、可审计的智能体 AI 驾驶辅助框架，将感知、合规推理、车辆状态解释与安全仲裁解耦为独立服务，目标是构建**辅助层**而非替代认证 ADAS 控制器，从而提升合规推理、可解释性与情境感知，并用 RSS 启发的保守约束兜底。

## 2. 方法论

### 核心思想
- 以 **DriveLM** 作为视觉-语言前端生成图结构场景理解（GVQA）与语言接地驾驶信息；关键合规字段（限速、辖区线索）由 DriveLM 输出经**结构化解析层**推导，而非注入模拟器真值。
- 通过 **MCP（Model Context Protocol）** 暴露三个专家服务器，由**有状态编排图**（LangGraph 风格）协调，最终经 **RSS/TTC 启发式安全仲裁器**过滤“说（SPEAK）vs 做（ACT）”。

### 关键技术细节
- **类传感器感知栈**：RGB 前视相机 + LiDAR；2D 检测器（YOLO）、LiDAR 距离细化、恒速 Kalman 跟踪、CARLA 地图车道/路线接口；刻意避免使用模拟器真值身份与标志元数据。
- **DriveLM 派生事实解析**：流程为 `image → DriveLM → sign reading → parser → speed_limit_kph = 80`；解析器做数值抽取、单位归一化、schema 校验并返回置信度；低置信度触发保守回退与规则查询。
- **world_state 表示**：分 Ego / Environment / Actors 三组；每个字段为 `(value, confidence, provenance)`，缺失或低置信字段留空并由保守默认处理。
- **事件提取与工具路由**：`E = {e_i | g_i(φ(world_state), c(world_state)) > η_i}`，事件如 `foreign_sign`、`jurisdiction_change`、`dynamic_limit_update`、`low_friction`、`vehicle_fault`，实现按需选择性调用。
- **Rules MCP 服务器**：混合检索评分 `S(q,d) = (1-λ)·BM25(q,d) + λ·cos(φ(q),φ(d))`；rulepack 版本化（DEU-v1、GBR-v1、DEU-v1-VSL），含内容哈希、effective_date 与冲突优先级（法规 > 官方标志表 > 次级指南），输出 `{legal_action, limit, citations, confidence}`。
- **Weather MCP 服务器**：输出 `{μ_est, risk_level, speed_factor, confidence}`，将法定限速缩放为牵引力感知建议。
- **MCP-CAN 服务器**：桥接 CAN/OBD-II 遥测与 DTC，只读默认，信号按纵向控制、横向状态、健康指标分组按需请求；提供 DTC 到用户可读解释的翻译层。
- **安全指标与风险**：
  - `TTC = d / max(ε, Δv)`
  - `rss_viol = 1[d < d_min(v, μ_est)]`
  - `d_min(v, μ_est) = v·t_r + v²/(2·a_brake(μ_est)) + d_0`，`a_brake = μ_est·g`
  - 健康分数 `h = σ(Σ_k w_k·ψ_k(can_signals))`
  - 风险 `r = α·max(0, (τ - TTC)/τ) + β·rss_viol + γ·h`
- **说 vs 做仲裁**：`U_act = r - C_act - C_err`，`U_speak = B_adv·r - C_fat`；`decision = ACT` 当 `(U_act - U_speak) > Δ 且 rss_viol = 1`，否则 `SPEAK`。
- **有界在线自适应**：通过反馈事件对 `Δ` 与 `C_min` 做有界单调更新，减少迟报同时抑制假阳性。
- **编排 tick（算法 1）**：更新 world_state → 提取事件 → 路由工具 → 并行调用（带超时）→ 融合 → 计算安全指标 → 仲裁 SPEAK/ACT → 记录 trace、更新记忆与有界反馈。

## 6. 主要结论与发现

- **合规与安全**：DriveMCP 在三类场景中取得最低违规率（0.2–0.3 次/10 km）与最低超速（0.6–0.9%），优于 VLM-Direct、VLM-Direct+RAG 与 VLM-Tools-NoArbiter。
- **危险响应**：DriveMCP 危险响应约 0.69–0.73 s，显著快于 VLM-Direct（1.02–1.10 s）与 VLM-Direct+RAG（0.95–1.05 s）。
- **延迟**：DriveMCP 保持亚秒级建议延迟（0.29–0.31 s）；VLM-Tools-NoArbiter 最低（0.25–0.27 s）但会触发不必要的升级。
- **鲁棒性**：漏/误读限速主要损害合规指标，actor 丢失主要损害危险响应；30% 漏标志使事件 F1 从 92% 降至 70%，正确工具率从 94% 降至 76%。
- **仲裁敏感性**：Δ 增大减少干预频率与假阳性，但会延迟升级、降低首次升级时 TTC。
- **消融**：移除 Rules 中的 RAG 是违规增加的主导因素（0.20 → 0.90 次/10 km）；移除工具并行主要影响延迟；oracle 元数据变体显示 DriveLM 派生事实与真值之间仍有差距（0.20 vs 0.15）。
- **CAN 感知**：在退化制动包络下，CAN 上下文降低推荐目标速度（65 km/h）、提升 TTC（2.2 s）、减少近碰撞（0.2 次/10 km）。

- **统计强度**：每配置 10 次运行虽报告了 95% CI，但样本量偏小，长尾/极端场景的方差可能被低估。

## 9. 可复现性与开放科学

- **正面因素**：
  - 方法描述细致，给出了 world_state schema、事件触发条件、检索评分公式、TTC/RSS 公式、仲裁效用函数与完整编排伪代码（算法 1），理论上有助于复现核心逻辑。
  - 明确列出 rulepack 标识（DEU-v1、DEU-v1-VSL、GBR-v1）、CARLA 版本（0.9.8）与场景族定义。
  - 公平性控制描述清晰（共享 DriveLM checkpoint、同步传感器快照、固定 prompt）。
- **不足因素**：
  - 未提及代码、rulepack 语料、prompt 模板与配置文件的公开发布链接或补充材料。
  - 未报告随机种子管理、超参数完整列表（如 α、β、γ、λ、η_i、τ 的取值细节）、缓存/超时具体阈值。
  - 未报告硬件与运行时长，使端到端复现的时间与算力成本难以估计。
- **总体判断**：方法层面的可复现性较好（公式与流程可重建），但**制品（artifact）层面的可复现性不足**，属于"描述可复现、运行难复现"的类型。

## 10. 与相关工作的定位

- **相对单体 VLM 驾驶助手**（如 DriveLM 直接推理、VLM+RAG）：DriveMCP 的核心差异在于把"合规知识"从模型参数与长提示中剥离为可版本化的外部服务，并以事件触发实现按需调用，从而在可更新性、可审计性与延迟上取得优势。
- **相对经典模块化 ADAS 流水线**：本文并未重造感知—规划—控制栈，而是引入 **MCP 作为工具抽象层**与**语言模型作为语义前端**，把"规则理解与解释"这一传统上由人工编码的环节交给可检索、可引用的知识库。
- **相对 LLM Agent / Tool-use 框架**：多数 agent 工作关注任务完成度，本文额外引入 **SPEAK/ACT 仲裁**与 RSS/TTC 保守护栏，将"何时不该行动"显式建模，是面向安全关键场景的差异化设计。
- **相对合规推理研究**：以往工作多聚焦单一辖区或静态规则，本文通过 rulepack 版本化与冲突优先级（法规 > 官方标志表 > 次级指南）处理**跨辖区、动态限速**的规则演化问题。
- **定位总结**：DriveMCP 更像是一个**可审计的辅助层参考架构**，其贡献重心在系统集成与合规可追溯性，而非单点算法 SOTA。

## 11. 潜在影响与后续方向

- **工程影响**：rulepack 版本化 + 引用输出的模式，为"法规随地图/辖区热更新"提供了一条不重训模型的路径，对量产 ADAS 的 OTA 合规更新有借鉴意义。
- **研究方向**：
  - 将 VLM 前端替换为更强的时序一致模型，研究不确定性在模块间的传播与校准。
  - 引入形式化方法，为仲裁器提供可证明的安全边界，或对接已认证安全监视器。
  - 扩展 rulepack 覆盖（更多国家、州级差异、卡车/公交专用规则）并研究检索错误的检测与回退。
  - 开展硬件在环与真实道路的用户研究，量化信任校准、分心与过度依赖。
  - 研究工具层的安全加固：提示注入防御、工具输出签名与验证、CAN 数据最小化与差分隐私。
- **风险提示**：模块化在提升可维护性的同时也扩大了攻击面与故障组合空间，"更多组件"未必等于"更安全"，需以系统级失效分析（如 FMEA、STPA）配套评估。

## 12. 一句话总评

DriveMCP 以 **MCP 工具化 + rulepack 版本化 + RSS/TTC 仲裁** 的组合，把驾驶辅助中的"合规推理"从不可审计的模型内部行为，转化为可引用、可更新、可回退的外部服务流程；其在 CARLA 中的实验显示出更低的违规率、更快的危险响应与亚秒级延迟，但受限于纯仿真验证、感知栈简化、算力信息缺失与人因研究空白，当前更适合作为**可审计辅助层的架构参考**，而非可直接认证部署的安全方案。
