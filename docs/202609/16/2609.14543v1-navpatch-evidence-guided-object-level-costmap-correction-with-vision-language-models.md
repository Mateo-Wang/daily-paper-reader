## 摘要
移动机器人通常依赖几何地图进行避障和路径规划，但由此得到的障碍物表示并不总是与物体应如何影响导航相匹配。低矮的线缆可能被漏检，柔软的窗帘可能造成虚假的阻塞，而交通锥可能需要比其观测足迹更大的排除区域。我们提出 NavPatch，一种对象级校正层，通过视觉语言模型进行周期性场景理解，为导航相关物体类别分配 ADD、REMOVE 或 EXTEND 操作。开放词汇定位可定位物体实例，LiDAR 和 RGB-D 观测提供 3D 支持。观测质量过滤和跨帧维护决定每个校正补丁何时提交、替换或撤销。在五种布局下的 50 次真实机器人试验中，NavPatch 实现了 86.0% 的总体成功率。对四种配置共 200 次运行的消融研究表明，与仅基于当前观测的更新相比，NavPatch 将成功率从 70.0% 提升至 86.0%，并将错误提交率从 68.4% 降低至 40.7%。

## Abstract
Mobile robots typically rely on geometric maps for obstacle avoidance and path planning, but the resulting obstacle representation does not always match how an object should affect navigation. A low lying cable may be missed, a flexible curtain may create spurious blockage, and a traffic cone may require an exclusion region larger than its observed footprint. We present NavPatch, an object level correction layer that assigns ADD, REMOVE, or EXTEND to navigation relevant object categories through periodic scene understanding with a vision-language model. Open vocabulary grounding localizes object instances, and LiDAR and RGB-D observations provide 3D support. Observation quality filtering and cross frame maintenance determine when each correction patch is committed, replaced, or revoked. In 50 real robot trials across five layouts, NavPatch achieves an overall success rate of 86.0%. An ablation study of four configurations with 200 runs in total shows that NavPatch improves the success rate from 70.0% to 86.0% and reduces the false commit rate from 68.4% to 40.7% compared with updates based only on the current observation.

## 1. 核心问题与整体含义

- **研究动机**：移动机器人通常依赖几何代价地图进行避障与路径规划，但几何占据只表示“哪里被观测到”，不一定表示“物体应如何影响导航”。
- **典型不匹配**：
  - **漏检阻塞（missing blockage）**：低矮线缆等物体可能被几何地图弱表示或漏检。
  - **虚假阻塞（spurious blockage）**：可穿越窗帘等柔性物体可能被几何传感器当作障碍。
  - **排除范围不足（insufficient exclusion extent）**：交通锥等物体需要比其物理足迹更大的禁行/排除区域。
- **整体含义**：论文提出 NavPatch，将视觉语言模型（VLM）的场景理解转化为对象级代价地图修正操作，即 **ADD、REMOVE、EXTEND**，以弥合几何地图与导航语义之间的差距。

## 2. 方法论

### 2.1 核心思想

- 在导航过程中周期性使用 VLM 理解当前 RGB 场景，识别导航相关物体类别，并为每个类别输出检测短语、地图动作、置信度；对 EXTEND 还输出方向与范围级别。
- 使用开放词汇检测与分割定位对象实例，并用 LiDAR 与 RGB-D 提供 3D 支撑。
- 将类别级提案转化为实例级局部修正区域，再通过观测质量过滤与跨帧证据维护决定补丁的 **COMMIT、REPLACE、REVOKE**。
- 最终将修正补丁与基础几何代价地图融合，供下游规划器使用。

### 2.2 关键技术细节

- **周期 VLM 场景理解**：
  - 使用 Qwen3-vl-flash，频率约 **0.2 Hz**。
  - 结构化提示要求输出物体类别、检测短语、地图动作、置信度。
  - 固定置信度阈值 **0.65**，低置信度提案被拒绝。
  - 每个物体类别仅保留一个当前修正提案，直到下一次 VLM 更新。

- **开放词汇实例定位与 3D 点提取**：
  - GroundingDINO 根据检测短语定位物体，SAM 2.1 根据边界框生成实例掩码。
  - 二者在真实机器人实验中约 **6 Hz** 运行。
  - LiDAR 点投影到图像掩码内作为候选；RGB-D 深度像素在有效范围内反投影到 3D。
  - 使用 3D 欧氏聚类，距离阈值 **0.12 m**；少于 3 点的簇丢弃。
  - 选择距相机中位距离最小的簇；若至少包含 **8 点**，作为该模态的当前 3D 支撑。

- **动作条件局部地图修正**：
  - **ADD**：将当前 LiDAR 与对齐深度 3D 点分别投影到地面并栅格化，形成候选障碍区域。
  - **REMOVE**：仅使用与实例掩码关联的 LiDAR 点，栅格化后通过膨胀-腐蚀填补小孔，并加固定边距形成清除区域。
  - **EXTEND**：VLM 选择三种模式之一：
    - **AROUND**：物体周围圆盘；
    - **ACROSS**：垂直于机器人-物体连线、以物体为中心的条带；
    - **BEHIND**：从物体向远离机器人方向延伸的矩形。
  - 范围级别为 small / medium / large，对应 **0.30 m / 0.80 m / 1.50 m**。

- **观测质量过滤**：
  - 对每个实例 i、模态 m，质量分数为：
    - \(q_{i,m}=q_{bnd,i}\cdot q_{pts,i,m}\cdot q_{clu,i,m}\)
  - 其中：
    - \(q_{bnd}\)：掩码像素位于图像边界带之外的比例，反映截断风险；
    - \(q_{pts}\)：3D 点支撑是否充足，参考计数 \(N_{ref}=16\)；
    - \(q_{clu}\)：掩码关联点是否集中在所选簇中。
  - 单模态阈值 \(q_{min}=0.40\)。
  - 若仅一个模态通过，直接使用其区域；若两个都通过，区域取并集，观测权重取较大质量分数。
  - 若均未通过，该观测不进入时间更新。

- **跨帧补丁维护**：
  - 将当前区域关联到已有同类实例，依据区域重叠、质心距离、最小区域距离；找不到则创建新实例 ID。
  - 在 **1.5 s** 窗口内累积证据，证据采样间隔至少 **0.20 s**。
  - 累积证据 \(E=\sum q\)，当 \(E\ge E_{min}=1.0\) 时，区域被确认并通过 **COMMIT** 写入地图。
  - 已提交补丁若与后续区域差异较小则保留；差异显著条件包括：
    - 质心位移至少 **0.20 m**；
    - 相对面积变化至少 **50%**；
    - 与当前补丁 IoU 低于 **0.35**。
  - 新区域证据足够后通过 **REPLACE** 替换旧补丁，实例 ID 不变。
  - 每次有效更新刷新 **20 s** 生命周期；超时未更新则 **REVOKE**。

- **代价地图融合**：
  - 修正代价地图以 **5 Hz** 发布。
  - ADD 与 EXTEND 映射为非可通行单元；REMOVE 清除在线障碍层中的虚假阻塞。
  - 同一单元冲突时，ADD/EXTEND 的非可通行状态优先于 REMOVE。
  - REMOVE 不覆盖静态地图中的占据或未知单元。

## 3. 实验设计

- **实验场景 / Benchmark**：
  - 使用真实机器人平台 Ranger Mini V3，配备 Livox MID360S LiDAR 与 Intel RealSense D435 RGB-D 相机。
  - 全局规划器为 Hybrid A*，局部规划器为 TEB。
  - 五个固定真实世界布局：
    - Mixed-A：两个交通锥、一个窗帘、一个地面线缆；
    - Mixed-B：倾斜窗帘、泡沫板、地面线缆簇、交通锥、额外箱子；
    - ADD-focused：泡沫板与两个地面线缆；
    - REMOVE-focused：一个窗帘；
    - EXTEND-focused：两个交通锥、带禁止进入标志的箱子、一个地面线缆。
  - 共标注 **17 个导航相关物体实例**：8 个 ADD、3 个 REMOVE、6 个 EXTEND。
  - 使用手动标注 ground truth，动作一致、一对一空间匹配，容差 **0.25 m**。
  - 在 REMOVE 布局中，机器人必须穿过窗帘而不是绕过。
  - 使用 RGB 视场确定每次运行的有效评估区间。
  - 这不是公开数据集 benchmark，而是自建真实机器人闭环导航评测。

- **评价指标**：
  - **Success Rate, SR**：无碰撞到达目标的运行比例。
  - **False Commit Rate, FCR**：提交补丁中动作或位置不匹配 ground truth 的比例。
  - **Missed Commit Rate, MCR**：可见 ground truth 物体中未被正确提交补丁的比例。
  - **Patch Update Rate, PUR**：路由观测中改变已提交补丁的比例。

- **对比方法 / 配置**：
  - 完整 NavPatch 系统评估：50 次闭环试验，五个布局各 10 次。
  - 消融研究四种配置：
    - **Frame-wise**：直接使用当前实例观测更新地图；
    - **Quality-only**：在 Frame-wise 基础上加入观测质量过滤；
    - **Temporal-only**：仅使用跨帧补丁维护，无质量过滤；
    - **NavPatch**：质量过滤 + 跨帧维护 + 质量加权证据。
  - 四个配置共享相同视觉语义前端、3D 点提取流程与导航后端。
  - 未与 Interactive Navigation、BehAV、NORM-Nav、E2Map、Language as Cost 等外部方法进行直接实验对比，这些仅在相关工作中讨论。
