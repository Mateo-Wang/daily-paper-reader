## 摘要
世界动作模型（WAMs）利用视频生成模型预测机器人操作中的未来视觉动力学，但迭代去噪会给闭环控制带来额外延迟。我们通过实验发现，去噪过程中视觉内容以不同速率收敛。静态背景结构较早形成，而夹爪与被操作物体在第一步之后仍然模糊，其交互动力学只有通过后续去噪才会显现。因此，简单地将多步视频模型截断为一步，虽然保留了场景结构，却丢失了对操作最为关键的交互中心动力学。为解决这一问题，我们提出 DIDO，将多步视频模型收敛后的动力学蒸馏到单步去噪中。DIDO 将分布匹配蒸馏与交互中心表示引导相结合。除了将多步生成压缩为一次前向传播外，DIDO 还使用有监督的边界框视觉推理 token 显式建模夹爪、被操作物体及其交互。此外，DIDO 将目标物体在多个模型层中的表示与预训练 DINOv3 编码器的特征对齐。这种交互中心引导有助于蒸馏模型在单步中同时保留相关实体及其未来动力学，同时显著降低推理延迟。DIDO 在 LIBERO 上达到 99.0% 的平均成功率，在 LIBERO-Plus 上达到 76.6%，在 RoboTwin 上达到 92.0%，同时还展示了向真实世界机器人操作中的长时程任务与泛化任务的有效迁移。

## Abstract
World Action Models (WAMs) use video generation models to predict future visual dynamics for robotic manipulation, but iterative denoising introduces additional latency for closed-loop control. We empirically find that visual content converges at different rates during denoising. Static background structure forms early, whereas the gripper and manipulated object remain blurry after the first step, with their interaction dynamics emerging only through subsequent denoising. Consequently, naively truncating a multi-step video model to one step preserves scene structure but loses the interaction-centric dynamics most critical for manipulation. To address this issue, we propose DIDO, which distills the converged dynamics of a multi-step video model into a single denoising step. DIDO combines distribution matching distillation with interaction-centric representation guidance. Beyond compressing multi-step generation into one forward pass, DIDO explicitly models the gripper, manipulated object, and their interaction using supervised bounding-box visual reasoning tokens. Additionally, DIDO aligns the target object's representations across multiple model layers with features from a pretrained DINOv3 encoder. This interaction-centric guidance helps the distilled model preserve both the relevant entities and their future dynamics in a single step, while substantially reducing inference latency. DIDO achieves an average success rate of 99.0\% on LIBERO, 76.6\% on LIBERO-Plus, and 92.0\% on RoboTwin, while also demonstrating effective transfer to long-horizon and generalization tasks in real-world robotic manipulation.

# DIDO 论文深度总结

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：视觉-语言-动作模型（VLA）已能较好地跟随语言指令完成操作任务，但大多直接从当前观测预测动作，**不显式建模环境在动作作用下的演化**。世界动作模型（WAM）通过视频生成模型预测未来视觉动力学，为策略提供"前瞻"能力。
- **核心矛盾**：WAM 依赖**迭代去噪**生成未来视频，给闭环控制带来显著推理延迟。一个自然的加速思路是截断去噪、只用一步或前几步的表示。
- **关键实证发现**：作者观察到去噪过程中视觉内容**收敛速率在空间上不对称**：
  - 静态背景结构在第一步就基本成形；
  - 夹爪与被操作物体在第一步后仍然模糊；
  - **交互动力学（夹爪-物体耦合运动）只在后续去噪步骤中逐步显现**，并在隐空间中逐渐空间局部化。
- **问题定义**：简单地把多步视频模型截断为一步，会保留场景结构却**丢失对操作最关键的交互中心动力学**。DIDO 的目标就是：在单步去噪中恢复这些交互中心动力学，同时保持低延迟。

## 2. 方法论

### 2.1 核心思想
将多步视频模型收敛后的动力学**蒸馏到单步生成器**，并通过**交互中心表示引导**（边界框轨迹监督 + 多层视觉特征对齐）显式补偿单步截断所丢失的交互动态；再通过混合 Transformer 架构把该单步世界模型与动作专家耦合，使策略可直接访问其内部表示而无需解码未来帧。

### 2.2 关键技术细节

- **基础模型**：基于 Wan2.2-TI2V-5B，初始化自其公开的 4 步蒸馏检查点，并先在机器人演示数据上微调得到"机器人域 4 步教师"。

- **阶段一：单步动力学蒸馏（DMD）**
  - 用分布匹配蒸馏（DMD）将 4 步教师压缩为单步生成器，优化目标为扰动分布的 KL 散度：`L_DMD = E_t[D_KL(p_θ,t ‖ p_T,t)]`。
  - 梯度用 fake score 与 target score 之差估计；教师噪声水平从 `{1000, 750, 500, 250}` 中采样；使用归一化梯度代理 `g_DMD = (x̂_F0 − x̂_T0) / mean|x_g − x̂_T0|`，并在线更新 fake score 网络（生成器每 5 次迭代更新一次）。
  - 与"直接截断教师第一步"不同，DMD 训练单步生成器**匹配教师的收敛输出分布**。

- **交互中心视觉推理（四组 token）**
  - 定义 `T_inter = [T_obj; T_int; T_grip; T_align]`，共 64 个 token（每组 16 个），嵌入视频 Transformer 并与其潜在表示共同演化。
  - **轨迹监督**：`[T_grip; T_int]` 预测 `H_a=32` 步夹爪边界框序列，`[T_obj; T_int]` 预测物体框序列；共享 `T_int` 以捕捉二者的相对时空演化。损失为 smooth-L1 + GIoU 加权和：`L_box = (1/H_a)Σ[smoothL1 + λ_giou·L_giou]`，总交互损失 `L_inter = λ_obj·L_box(obj) + λ_grip·L_box(grip)`。
  - **多层视觉对齐**：用冻结的 DINOv3 编码器对目标物体裁剪区域编码，将若干 Transformer 层中 `T_align` 的表示经投影 `P_l` 对齐到 DINOv3 特征：`L_align = (1/|S|)Σ_l ‖P_l(T_align^l) − F_DINO‖_1`。DINOv3 仅用于构造训练目标，推理时移除。

- **动力学引导的 token 精炼**
  - 用当前帧与未来帧的 value 特征差构造动力学图：`s_tk(r) = ‖V_tk(r) − V_t0(r)‖_2`。
  - 将空间特征图划分为 4×5 网格（每区域 4 个细粒度单元），按区域动力学得分排序，**保留 top-3 高动态区域的全分辨率 token，其余 17 个区域做 2×2 平均池化**，将条件上下文从 323 个 token 压缩到 191 个。

- **阶段二：交互感知动作预测**
  - 动作专家与视频模型通过 **mixture-of-transformers** 架构耦合，共享注意力：动作 token 可访问世界模型全部表示，而世界模型 token 对动作流保持掩码（非对称注意力），保留阶段一学到的预测通路。
  - 动作专家深度与视频模型相同、隐宽为其 1/4，输出维度适配各本体（LIBERO 为 7，RoboTwin/Galbot 为 14）。
  - 用**流匹配**生成动作块：构造 `a_τ = (1−τ)ε + τa`，目标速度 `u = a − ε`，损失 `L_act = E‖v_θ(a_τ, τ) − u‖²`。

- **两阶段训练目标**
  - `L_stage1 = L_DMD + L_inter + λ_align·L_align`
  - `L_stage2 = λ_video·L_video + λ_act·L_act + L_inter + λ_align·L_align`（阶段二去掉 DMD，保留视频生成目标作为训练信号）

### 2.3 数据自动标注
- 物体框：从语言指令解析目标实体，开放词汇检测器定位，视频跟踪器传播；夹爪框：仿真器状态投影（LIBERO/RoboTwin）或 Grounding DINO + SAM 3 检测跟踪（真实机器人）。
- 标注质量经人工审计：LIBERO 目标物体 95/100 轨迹正确，RoboTwin 181/200 正确，Galbot 40/40 全部正确。

## 6. 主要结论与发现

- **去噪动力学逐步显现**：用 4 步视频模型 + Action DiT 专家验证，去噪步数从 1 增至 4，LIBERO 从 97.7% 升至 98.4%，LIBERO-Plus 从 71.4% 升至 72.6%，证实后段去噪暴露更多动作相关动力学。
- **单步蒸馏有效**：DIDO 在 LIBERO 达 **99.0%**（超越 LingBot-VA/Faster-WAM 0.5 个点、Fast-WAM 1.4 个点、Flash-WAM 2.9 个点）；RoboTwin **92.0%**（无本体预训练方法中最优，超 Fast-WAM 0.2、Flash-WAM 6.5 个点）；LIBERO-Plus **76.6%**（超 Faster-WAM 1.6 个点，在机器人初始化、语言、光照、布局偏移上排名第一）。
- **真实世界泛化**：basic 协议 80.8（π0.5 为 74.5，Fast-WAM 为 53.8）；advanced 协议 66.0（π0.5 为 53.3，Fast-WAM 为 33.0），从 basic 到 advanced 的退化（14.8）小于两个基线。
- **效率与鲁棒性兼得**：单步未来建模在仅比"无想象"的 Fast-WAM 多 28 ms 延迟的前提下，LIBERO 提升 1.4 个点、LIBERO-Plus 提升 25.1 个点。
- **交互中心 token 高度有效**：仅占缓存 token 的 5.74%，却贡献 33.9% 的动作归因，每 token 归因密度约 5.9×；而 Current/Future Visual token 归因密度仅 0.61×/0.73×。

## 7. 优点

- **问题洞察扎实**：通过解码视频与隐空间双重证据揭示"背景先收敛、交互后收敛"的非对称性，为方法设计提供直接动机，而非经验性堆叠。
- **方法针对性强**：交互中心 token（物体/交互/夹爪/对齐）与轨迹监督、DINOv3 多层对齐形成互补——前者提供时空定位，后者保证判别性视觉信息；共享 `T_int` 的巧妙设计让两分支捕捉相对演化。
- **效率与精度平衡好**：单步生成 + 动力学引导 token 精炼（323→191 token，约降 30 ms），在保持高成功率的同时大幅降低延迟。
- **架构耦合合理**：非对称共享注意力让动作专家直接读取世界模型中间表示，避免解码-重编码未来视频的额外开销。
- **标注自动化**：无需人工标注，从原始演示自动生成边界框轨迹与视觉对齐目标，并附有质量审计数据。
- **实验公平性较好**：真实世界基线在同一数据、观测/动作空间、训练预算下重训；消融为累积式设计，便于量化各组件增量。

## 8. 不足与局限

- **监督粒度粗糙**：交互推理依赖边界框监督，对多物体交互、可变形物体、精细接触几何可能不足；自动标注在严重遮挡或指代模糊时会产生噪声监督。
- **训练流程复杂**：包含教师准备、单步蒸馏、联合策略学习三个独立优化阶段，比直接训练动作策略更繁琐，计算成本更高（RoboTwin 阶段二需约 100 小时）。
- **依赖教师质量**：单步世界模型蒸馏自机器人域 4 步教师，其预测能力受教师质量与数据覆盖度制约。
- **实验覆盖有限**：
  - 真实世界仅 4 个任务、80 次 rollout，统计效力有限；
  - LIBERO-Plus 相机偏移维度表现明显落后（45.3%），说明方法并非在所有分布偏移下都鲁棒；
  - 未单独消融 DINOv3 对齐、轨迹监督、各 token 组件的独立贡献；
  - 未涉及多本体、更广泛环境或跨具身迁移的系统验证。
