## 摘要
自动驾驶涉及多模式不确定性下耦合的决策与场景演化。为捕捉这种耦合与不确定性，我们提出 MM-Future，一种世界-动作模型，可生成多个成对的场景-动作假设，并对每对假设内的双向交互进行建模。每个假设由一个结构化动作先验和一个独立的未来场景源初始化，随后通过模态感知的扩散 Transformer 共同演化。为支持高效的多模式推演，MM-Future 将多视角视频压缩为面向规划的表示，称为 MM-Tokens。最后，一个以未来为条件的提议评分器根据共享的历史上下文及其成对的预测未来对轨迹候选进行排序。在 NAVSIM navtest 上，MM-Future 达到 94.0 PDMS 和 91.5 EPDMS，同时在 HUGSIM 的零样本闭环评估中获得 32.3 HD-Score。消融实验表明，相较于单模式与仅动作变体均取得一致提升，验证了多模式联合世界-动作建模的收益。

## Abstract
Autonomous driving involves coupled decision-making and scene evolution under multi-mode uncertainty. To capture this coupling and uncertainty, we introduce MM-Future, a world-action model that generates multiple paired scene-action hypotheses and models bidirectional interaction within each pair. Each hypothesis is initialized from a structured action prior and an independent future scene source, which are then co-evolved through a modality-aware diffusion Transformer. To support efficient multi-mode rollout, MM-Future compresses multi-view video into planning-oriented representations, dubbed MM-Tokens. Finally, a future-conditioned proposal scorer ranks trajectory candidates by shared history context and their paired predicted future. On NAVSIM navtest, MM-Future achieves 94.0 PDMS and 91.5 EPDMS, while attaining a 32.3 HD-Score in zero-shot closed-loop evaluation on HUGSIM. Ablations show consistent improvements over both single-mode and action-only variants, validating the benefit of multi-mode joint world-action modeling.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：端到端（E2E）自动驾驶直接将传感器观测映射为轨迹或控制指令；世界–动作模型（WAM）在此基础上额外建模驾驶场景的未来演化，从而支持"后果感知"的规划——不仅要推理"该做什么"，还要推理"可能发生什么"。
- **核心矛盾**：现有 WAM 主要分两类，各有短板：
  - **级联式（Cascaded）WAM**：场景优先（用预测视频/BEV 引导规划）或动作优先（先生成轨迹再推演对应未来）。影响是**单向**的，下游变量无法修正上游变量；虽能通过顺序条件化支持多模式，但缺乏双向耦合。
  - **联合式（Joint）WAM**：场景与动作在共享生成过程中**双向交互**，但通常只产生**单一配对 rollout**，缺乏模式覆盖。
  - 论文指出：**驾驶同时需要"双向耦合"与"模式覆盖"**。
- **典型例子**：在无信号交叉口，同一观测可导致两种结果——"加速"会促使他车让行、使自车通过；"减速"则让他车进入、强化自车等待的决策。这要求模型**双向共演化多个场景–动作对**。
- **三大挑战**：
  1. 每个训练片段只有**一个已实现的场景–动作结果**，如何从单一结果监督中学习多样的驾驶意图？
  2. 如何以可接受的计算代价生成**多个未来假设**（稠密视频 latent / 图像 patch / BEV 网格随预测时域与模式数增长而急剧膨胀）？
  3. 如何从多个配对假设中**识别最合适的动作**（仅凭历史观测可能不足以区分候选）？

## 2. 方法论

### 2.1 整体思想
将未来场景与自车运动建模为**联合条件分布**：给定观测 $O=(I_h, s_h, c)$，生成 $M$ 个成对模式 $\mathcal{H}^m=(\hat{\tau}^m, \hat{X}^+_m)$，即"轨迹 + 其专属未来场景 rollout"。每个模式由**结构化动作先验 + 独立场景噪声**初始化，经模态感知 Transformer 双向共演化，最后用未来条件评分器排序选优。框架含三部分：分块多视角编码器（MM-Encoder）、模态感知 Transformer 生成器、未来条件评分器。

### 2.2 规划导向的 MM-Tokens（高效场景表示）
- 用视觉骨干 $E$（DINOv2-S，LoRA 微调）对每相机抽取 **register tokens** $P^v_t$，避免传递全部稠密 patch token。
- 将时间轴分为 $C$ 个 chunk，每 chunk 内汇集所有帧、所有视角的 register tokens，用 $N_x$ 个**可学习 chunk 查询** $Q^{(j)}$ 通过自注意力聚合，得到 MM-Tokens $X^j\in\mathbb{R}^{N_x\times d}$。
- 目标编码器 $\bar{E}_{\bar\theta_e}$ 用 **EMA（衰减 0.999）** 更新，为未来图像序列提供稳定干净端点 $\bar{X}^+=\mathrm{sg}(\bar E_{\bar\theta_e}(I^+))$，训练时未来图像**只作目标、不入历史条件**。
- **不施加 RGB 或 BEV 重建约束**，MM-Tokens 完全由多模式联合世界–动作目标塑造；有限 token 预算促使其保留"可预测未来演化且与规划相关"的场景线索。
- 表示传播代价从 $\sum_{t\in T_j}\sum_v HW/p^2$ 降到 $N_x$，是支撑多模式 rollout 的关键。

### 2.3 多模式联合世界–动作流
- **结构化配对源**：将 GT 轨迹编码为连续动作 token $a_{gt}=E_a(\tau^{gt})$（每 token 含归一化差分运动 $(\Delta x,\Delta y,\sin\psi,\cos\psi)$，确定性解码器恢复绝对位姿）。对归一化训练轨迹做 **K-means**，用各簇经验均值与方差参数化**高斯混合噪声（GMN）**，采样 $M$ 个动作先验 $\{\epsilon_a^m\}$，各配一个独立未来 token 噪声 $\epsilon_x^m\sim\mathcal N(0,I)$，构成模式 $m$ 的初始场景–动作源对。
- **联合条件流**：对每个模态流 $\kappa\in\{a,x\}$ 独立采样流时间 $\rho_\kappa$，构造线性路径 $z_\kappa=(1-\rho_\kappa)\epsilon_\kappa+\rho_\kappa y_\kappa$；生成器 $G_{\theta_g}$ 在干净历史 MM-Tokens、含噪未来 MM-Tokens 与含噪动作 token 上预测两个干净端点。
- **模态感知 Transformer**：共享多模态注意力实现场景与动作的**双向交互**；模态特定的 **AdaLN 调制与 FFN 分支**保留两流各自的统计特性；**非对称块掩码**把历史视作干净前缀（历史 query 只看历史 key），动作与未来 query 可互看——于是"动作能对其想象中的演化场景作出反应，场景能对更新中的自车动作作出响应"。模式维折叠进 batch 维，**各模式共享参数但从不交换 token**。
- **Best-of-Many（BoM）监督**：因每个片段只有一个真实结果，若对所有 $M$ 个预测施加同一端点监督会将其拉向共同预测。故解码轨迹后仅选距离 GT 最近的模式 $m_{win}$，**用同一模式索引同时监督动作流与场景流**：
  - 采用 **x-prediction 参数化**（预测"指向干净点的速度"$\hat u_\kappa=(\hat y_\kappa-z_\kappa)/(1-\rho_\kappa)$）；
  - $\mathcal L_{BoM}=\sum_{\kappa}\lambda_\kappa\|\hat u_\kappa^{m_{win}}-u_\kappa^{m_{win}}\|_2^2$，只对获胜对施加速度监督；
  - 共享获胜索引既保持场景–动作对应关系，又避免所有源塌缩到条件均值。
- 推理时用**短 Euler 调度**（2 步）从噪声积分采样。

### 2.4 未来条件提议评分器
- 用 stop-gradient 的轨迹作为 proposal query，先经自注意力互相比较，再通过交叉注意力以历史 MM-Tokens 为条件（$D_h$）；第二解码器 $D_f$ 让每个 query **只条件于其配对未来**（未来注意力对 $m$ 呈**块对角**，模式 $m$ 只能看 $\hat X^+_m$，不得访问其他预测未来），并叠加当前自车状态嵌入 $g_s(s_0)$。
- 输出模块 $H$ 预测各 **PDMS 分量 logits**，用官方训练期伪仿真器生成标签 $y^m$，损失为 $\mathcal L_{score}=\frac1M\sum_m \mathrm{BCEWithLogits}(\ell_m,y^m)$。
- 对轨迹提议与未来 MM-Tokens **停止梯度**，防止生成器为简化评分任务而扭曲输出。
- **总损失**：$\mathcal L=\mathcal L_{BoM}+\lambda_s\mathcal L_{score}$；在线 MM-Encoder、联合生成器、评分器联合优化，目标编码器仅 EMA 更新。

## 6. 主要结论与发现

- **开环规划**：NAVSIM-v1 上 MM-Future (trainval) 达 **94.0 PDMS**，超过最强 WAM 基线 DriveFuture 3.3 分、超过最强 E2E 基线 DrivoR (trainval) 0.3 分；train-only 设置下亦以 93.4 vs 93.1 领先 DrivoR (train)。NAVSIM-v2 上达 **91.5 EPDMS**，超过最强总基线 UniTeD 1.4 分、最强 WAM 基线 DriveFuture 1.6 分。同时在 v1 取得最高 EP（91.6）、v2 取得最佳 TTC（98.6）与近最佳 EP（92.2），表明在保持行驶进展的同时维持了碰撞安全性。
- **闭环迁移**：HUGSIM 零样本闭环下取得最高平均 **HD-Score 32.3**，超过 Latent-WAM 3.4 分；优势在 Medium 难度

难度档位上尤为突出，同时在 Easy 与 Hard 档位也保持领先或接近领先，说明该方法的优势并非仅来自某一类简单场景，而是具有跨难度的一致性。此外，MM-Future 在闭环中展现出更强的**恢复能力**：由于每步规划都会改变后续观测，具备多模式未来推理能力的模型能更好地应对自身决策引发的分布偏移。

- **核心机制验证**：
  - **多模式 + 配对**是关键：消融显示，仅增加假设数而不做场景–动作配对（只有动作多模式）带来的增益明显低于"成对多模式"；配对生成使各模式的未来场景真正分化，从而为规划提供互补证据。
  - **双向耦合优于单向**：在相同参数量下，"Mixture-of-DiT 双向"配置优于单 DiT 双向，更明显优于单向条件化配置，印证了"动作能对其想象的场景作出反应、场景能响应自车动作"这一设计假设。
  - **未来条件评分有效**：加入"配对未来"作为评分条件后，相比仅用历史条件的评分器有稳定提升，说明未来 rollout 中确实包含区分候选动作的额外信息。
  - **规模效应**：随假设数从 1 → 16 → 32 增加，性能单调提升并逐渐趋于饱和，符合"模式覆盖度"的预期；但延迟也相应上升，需在精度与实时性间权衡。

- **定性观察**：MM-Token 注意力可视化显示，不同模式在右转、左转、低照度排队等场景下会自动聚焦于与各自未来假设相关的区域（如对向车道、路口冲突点、前车尾灯区域），表明模型学到的并非全局均匀注意力，而是**模式特异、规划导向**的场景表征。

## 7. 局限性与批判性分析

- **监督信号的根本张力未彻底解决**：BoM 监督本质上是"赢家通吃"，虽然避免了模式塌缩，但每个训练片段仍只有一个真实结果，**非获胜模式得不到直接监督**。这可能导致非获胜模式质量参差，或在训练早期形成"假多样性"（模式在 token 空间分散但语义上不可行）。论文未对非获胜模式的合理性做系统评估。
- **计算成本仍偏高**：主结果使用 64 对假设，单次前向 233 ms（H800、bf16、batch 1），对于需要高控制频率的实时部署仍有压力；论文虽给出 16/32 假设的低延迟配置，但未报告这些配置下的完整性能，难以判断能否在精度可接受的前提下满足实时要求。
- **评分器依赖伪仿真器标签**：评分器用官方训练期伪仿真器生成 PDMS 分量标签，其质量直接决定评分器的可靠性；论文未分析伪仿真器标签噪声对排序的影响，也未与真实闭环指标做相关性验证。
- **闭环评测范围有限**：仅在 HUGSIM 上做零样本迁移，未做微调上限评估，也未在其他闭环基准（如 CARLA 系、nuPlan 闭环）验证，结论的泛化性有待加强。
- **消融覆盖不均衡**：核心消融集中在 NAVSIM-v1，v2 与 HUGSIM 上未重复，无法确认各设计要素在扩展指标与闭环设定下是否同样必要。
- **训练算力信息缺失**：未报告 GPU 数量、型号与总训练时长，削弱了可复现性与成本评估的透明度。

## 8. 可复现性与工程可行性

- **正面因素**：方法建立在公开基准（NAVSIM、HUGSIM）与公开骨干（DINOv2-S + LoRA）之上；超参数（历史 2s / 未来 4s、2 Hz、64 token、16 层、宽度 1024、AdamW、25 epoch、batch 64、lr 2e-4、权重 1.0/0.1/1.0、2 步 Euler、64 假设）报告较为完整；损失设计与网络结构描述清晰，具备复现基础。
- **风险因素**：GMN 的动作先验需对归一化训练轨迹做 K-means 并估计各簇均值/方差，簇数等细节若未公开会影响复现；伪仿真器标签的生成流程依赖官方实现；训练资源未披露，复现成本难以预估。
- **工程可行性**：多模式 rollout 的表示代价通过 MM-Tokens 得到有效压缩，是该方法能扩展到 64 假设的关键工程贡献；但 64 假设的延迟意味着其更适合作为"高质量规划参考"或离线/半离线场景，而非直接上车的实时控制器。

## 9. 整体评价与启示

- **理论贡献**：论文精准识别了 WAM 中"双向耦合"与"模式覆盖"两个此前被割裂对待的需求，并给出统一框架：用**结构化动作先验（GMN）+ 独立场景噪声**构造成对模式源，用**模态感知 Transformer** 实现场景–动作双向共演化，用 **BoM 监督**在单结果数据上维持模式多样性，用**未来条件评分器**从多假设中选优。这一"配对生成 + 配对评分"的闭环设计具有方法论上的完整性。
- **工程贡献**：MM-Tokens 以"规划导向、无重建约束、有限 token 预算"的方式压缩多视角时序观测，把表示传播代价从稠密 patch 降到固定 token 数，是支撑多模式 rollout 的关键使能技术。
- **实证贡献**：在 NAVSIM-v1/v2 与 HUGSIM 零样本闭环上同时取得领先，且在匹配的 train-only 设置下仍优于强基线，说明增益来自方法本身而非数据规模。
- **启示**：驾驶规划中的"不确定性"不应仅建模为轨迹分布，而应建模为**场景–动作联合分布**；未来场景的价值不仅在于"预测得准"，更在于"能区分动作"。这一视角对未来 WAM 与 VLA 的结合、以及对世界模型评测指标的重新设计（从预测精度转向决策增益）都具有参考意义。
- **待跟进方向**：非获胜模式的监督与评估、评分器与真实闭环的一致性、更低延迟下的性能保持、以及跨闭环基准的泛化验证，是该工作最值得后续研究补足的几个方向。
